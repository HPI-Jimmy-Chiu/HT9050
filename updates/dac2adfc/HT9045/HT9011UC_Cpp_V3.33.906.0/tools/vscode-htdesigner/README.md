# HTML 視覺設計工具（VS Code 外掛）

像 WPF 設計工具那樣看、改 web HMI 的頁面（`web\page\*.html`）。
**不只 HT9045**：BCB6 表單移植成「網頁 HMI ＋ C++」的軟體都能用（見下面「用在其他軟體」）。

> 要接手開發這個外掛：先讀 [`HANDOVER.md`](HANDOVER.md)（流程、規則、待辦、踩過的坑）；每一版改了什麼與怎麼測的在 `WPF_DIFF_LOG.md`。

- 在 VS Code 裡看到頁面的真實樣子
- 點一個元件，就會顯示它的 **DFM 屬性** 和 **事件**
- **雙擊事件**，直接跳到那個事件的程式碼
- 在畫面上直接雙擊元件，會跳到它的預設事件（通常是 OnClick）；**還沒有就新增**（C++ 函式＋網頁連線），跟 WPF 一樣
- **拖曳移動、拉控制點改大小、方向鍵微調、在屬性面板改值**，改的是 HTML 原始碼，Ctrl+Z 復原、Ctrl+S 存檔
- 剪下／複製／貼上／刪除、工具箱新增元件、群組、順序、鎖定、隱藏、格線、框選 —— WPF 設計工具的操作都有
- 頁面清單、所有頁面一起搜尋、跟 DFM 比對、接線總覽與接線標示、頁面檢查（問題面板＋修正）

> **只想知道「怎麼做」**：看 [操作一覽](CHEATSHEET.md)（「元件」欄標題列的鍵盤圖示，或命令「HTML設計: 操作一覽」）。
> 每一版多了什麼：[更新紀錄](CHANGELOG.md)。
>
> `AI(W906-HTDESIGNER) 20260929` 建立。純 JavaScript，不需要 npm／Node.js。

## 安裝

```powershell
# 在移植樹根目錄
powershell -NoProfile -ExecutionPolicy Bypass -File tools\vscode-htdesigner\pack.ps1
code --install-extension tools\vscode-htdesigner\dist\ht9045-html-designer-<版本>.vsix --force
```

**裝好新版後，已經開著的 VS Code 視窗要重新載入一次才會換成新版**（不重新載入就一直跑舊版）。不用記指令：
- 外掛自己會發現有新版（最慢一分鐘；切回 VS Code 視窗時馬上看），**左下角狀態列出現「🔄 設計工具新版 v…：按這裡更新」**，右下角也會跳通知，按「現在更新」。
- 或按側邊欄「頁面」標題列的 🔄 按鈕（「重新載入視窗」）。
- 重新載入後，開著的頁面會自己再打開，還沒存的檔案也還在。

現在跑的是哪一版，看側邊欄「頁面」標題旁邊的版本號（例如 `v0.62.0`）。
⚠ 0.62.0 以前的版本沒有這個按鈕：第一次從舊版換過來，請**把 VS Code 關掉再打開**（或 `Ctrl+Shift+P` →「Developer: Reload Window」／「開發人員: 重新載入視窗」），之後就都用按鈕。
左邊活動列會多一個「HTML 視覺設計」圖示。這份說明隨時可以用「HTML設計: 設計檢視使用說明」（或元件樹標題列的 ? 圖示）打開。

移除：延伸模組面板找「HTML 視覺設計工具」→ 解除安裝。

## 用在其他軟體

同樣架構（BCB6 表單 → 網頁 HMI ＋ C++ 移植）的軟體都可以用，資料夾**照結構自動找**，名字不用跟 HT9045 一樣：

| 找什麼 | 怎麼認 | 自動找不到時的設定 |
|---|---|---|
| 網頁資料夾 | 裡面有 `page\`（頁面在 `page\*.html`） | `ht9045Designer.webRoot` |
| C++ 移植樹 | 有 `tools\dfm2rc\` 和 `forms\`（名字有 `_Cpp_` 的優先）；DFM 資料在 `tools\dfm2rc\ir_out` | `ht9045Designer.portRoot` |
| BCB6 原始碼 | 有 `main.dfm` 或 `main.cpp`（名字有 `_Code_V` 的優先，唯讀、Big5） | `ht9045Designer.goldenRoot` |

頁面的 `<title>` 寫了對應哪個 `.dfm`，就能比對 DFM、找事件程式碼。
設定名稱和命令代號還是 `ht9045Designer.*`（第一個用它的專案），這樣之前的設定、快捷鍵都不會失效；畫面上看到的名字都是通用的「HTML 視覺設計」。
看它找到了哪些資料夾：命令「HTML設計: 顯示偵測到的資料夾與索引狀態」。

## 怎麼用

**開啟一頁**（任選一種）：

- **「頁面」上面的搜尋框**（像 Visual Studio 方案總管上面那個）：打字就篩選下面的頁面清單——頁面名稱、標題、元件名稱、型別、
  畫面上的文字都找（空白隔開＝每個字都要有）。符合的頁面展開，底下列出符合的元件（找到的字會標亮），**點元件＝開那一頁並選取它**。
  Enter 開第一個、Esc 或 ✕ 清除、↓ 到清單；在「頁面」清單按 `Ctrl+F` 會跳回搜尋框。篩選中「頁面」標題列有「清除搜尋」按鈕。
- **左下角狀態列的「📄 頁面名稱 ⌄」**：點一下＝選一頁（打字可以篩選）；清單最上面一項可以把側邊欄的「頁面」叫回來。
- 側邊欄的「頁面」不見了（被收起或隱藏）：命令「HTML設計: 在側邊欄顯示『頁面』清單」，或點側邊欄最上面的「…」勾「頁面」。

- 左邊「HTML 視覺設計」最上面的 **「頁面」**：所有頁面照名稱前綴分組（Main／Setup／HW／Data／Status／Alert／Config／IDE／其他／web 根目錄，
  後面是頁數），每一頁顯示短名稱和它的標題（例如 `HotPlate　Hot Plate（cHotPlate.dfm …）`）。**點一下就換到那一頁**。
  目前這一頁標「● 目前」（橘色眼睛圖示）、其他開著的標「○ 已開啟」；換頁時清單會自己捲到目前那一頁、打開它的分組。
  滑鼠移到一頁上，右邊的 `</>` 圖示＝用文字編輯器開 HTML 原始碼（右鍵選單也有）。轉址頁標「→ 目標」。
  web 資料夾裡新增／刪除 .html，清單會自己更新；標題列的重新整理圖示可以手動重讀。在清單裡直接打字可以篩選。
- **在所有頁面搜尋**：「頁面」標題列的放大鏡、畫面右鍵、或 `Ctrl+Alt+Shift+O`。輸入元件名稱、型別（`TGroupBox`）或畫面上的文字
  （`Save`、`存檔`；空白隔開＝每個字都要有），一次找全部 80 多頁；名稱完全相同的排最前面。
  選一個結果＝開那一頁、直接選到那個元件（在沒顯示的分頁裡會自動切過去）。
- 左邊「HTML 視覺設計」→「元件」標題列的清單圖示 → 選頁面
- `Ctrl+Shift+P` →「HTML設計: 選擇頁面開啟設計檢視」
- 在 `.html` 檔上按右鍵 →「在設計檢視開啟」
- 開著某個 `.html` 時，編輯器右上角的預覽圖示（會開在旁邊，像 WPF 的 XAML／設計分割畫面）

**設計畫面上的操作（跟 WPF 設計工具一樣）**：

| 動作 | 結果 |
|---|---|
| 按一下元件 | 選取它（按下時就選，跟 WPF 一樣），右邊「屬性與事件」顯示它的資料，四周出現 8 個控制點 |
| 按住元件拖曳 | 移動它；靠近旁邊元件或外框的邊緣／中線 5px 內會**自動對齊**並畫出紅色參考線（按住 Alt 不吸附）；跟同一排（或同一列）的鄰居距離接近 **8 px**（BCB6 的格線間距）時吸附在剛好 8 px，並在兩者之間畫一小段**藍線**（WinForms／WPF 的間距吸附線） |
| 拖曳控制點 | 改大小（角落兩個方向一起改），一樣有對齊線；**多選時整組一起**改同樣的量（跟 WinForms／WPF、Ctrl＋方向鍵一樣），一次＝一個復原步驟 |
| Ctrl＋點 ／ Shift＋點 | **多選**：加入或移出選取，最後點的是主要選取。整組可以一起拖曳、一起用方向鍵移動 |
| Ctrl＋拖曳 | **複製**（WinForms／WPF）：選取的元件複製一份，放在放開的地方（同一個容器、新名稱）；原本的不動，Ctrl+Z 一次復原 |
| 拖曳／拉控制點的時候 | 標籤即時顯示要寫進去的數值：移動時「left 62　top 16」、改大小時「248 × 48」 |
| 右鍵「顯示 → 顯示所有元件名稱」 | 每個元件左上角貼一個小標籤寫它的名字（再按一次關掉；狀態列顯示「名稱」） |
| 在表單空白處按住拖曳 | **框選**（WPF 一樣）：畫出藍色虛線框，放開後框裡**整個被框住**的元件都選起來（外層和裡面都被框住時只選外層）。**按住 Shift 拖曳＝從元件上開始也能拉框**（Blend），Shift＋點一下（不拖）照舊是加選 |
| Ctrl+A（或右鍵「全選」） | 選取**同一層**的全部元件（同一個 Panel／GroupBox／分頁裡）；沒選東西或選了表單＝表單最外層的全部 |
| 右鍵「選取同型別（整頁／同一層）」 | 選取跟目前這個**同一種 VCL 型別**的全部元件（例如整頁的 TLabel），狀態列說選了幾個；接著在屬性面板改字型／顏色就**全部一起改** |
| 方向鍵 | 移動 1 px；**Shift**＋方向鍵 10 px |
| **Ctrl**＋方向鍵 | 改大小 1 px；**Ctrl＋Shift**＋方向鍵 10 px |
| 雙擊元件 | 它的預設事件（按鈕／標籤 OnClick、輸入框／下拉 OnChange、Timer OnTimer、表單 OnCreate）：有就跳到程式碼，**沒有就新增**（同 WPF、BCB6） |
| Enter、**F7** | 檢視程式碼：預設事件有設定就跳到它，沒有就打開表單的 .cpp（不新增）——WPF 的「檢視程式碼」 |
| 右鍵 | 選取滑鼠下的元件，出現設計工具的選單：剪下／複製／貼上／刪除、檢視程式碼、跳到 HTML 原始碼、跳到 DFM 定義、選取上層、全選、選取同型別、找元件、「對齊與間距」「順序」子選單、放進新 Panel、改回 DFM；「顯示」子選單（名稱、接線標示、DFM 位置、Tab 順序、格線、縮放）、「檢查與比對」子選單（接線總覽、與 DFM 的差異、頁面檢查）、切換模式 |
| **F2**（設計畫面） | **直接在元件上改文字**（WPF 的 Edit control text）：出現文字框，Enter／點別處＝寫進去，Esc＝不改；打字時設計畫面的快捷鍵不作用，Ctrl+Z／Ctrl+Y 只管文字框 |
| 屬性面板的名稱方塊、**元件樹上的 F2**、右鍵「改名稱」 | **改名稱**（元件的 id，WPF 的 Name）：一起改 `title="名稱 : 型別"` 和 `<label for>`；文字還是舊名稱的（新拉的 `Label1`），文字也跟著改（BCB6 的習慣）。DFM 裡有這個名稱、或網頁程式有用到它，會先問（那些不會跟著改）。Ctrl+Z 復原 |
| Esc | 選上一層（外層的 GroupBox／Panel…）；已經是最外層就取消選取 |
| Tab ／ Shift＋Tab | 選下一個／上一個元件 |
| Ctrl＋Z ／ Ctrl＋Y | 復原／重做（VS Code 原本的功能，一次拖曳或一串方向鍵＝一步） |
| Ctrl＋S | 存檔 |
| Ctrl＋滑鼠滾輪 | **縮放** 12.5%～800%，以滑鼠所在的位置為中心（右下角和狀態列顯示比例）；拖曳距離會換算回頁面的 px。拖曳、拉大小、框選到一半按 **Esc**＝取消、放回原位。「HTML設計: 設計檢視縮放回 100%」還原 |
| 按住**空白鍵**拖曳、或按住**滑鼠中鍵**拖曳 | **平移畫面**（WPF／Blend 的手形工具，游標變成手）；放大之後看別的地方很方便。平移時不會選到、移到任何元件 |
| Alt＋點 | 選最內層的 HTML 元素（沒有 id 的也可以）；**再按一次 Alt＋點＝選下面那一層**（Blend：一層一層往下，到底再回到最上面） |
| 點分頁標籤 | 照樣切換分頁 |
| 要操作頁面本身（展開下拉選單等） | 按編輯器右上角的鉛筆圖示（或狀態列）切到「操作模式」，再按一次切回來 |

**多選時的對齊**（WPF 的「格式 → 對齊」）：屬性面板最上面出現「多選：對齊與大小」，
有 靠左／水平置中／靠右／靠上／垂直置中／靠下／同寬／同高／同大小，**以主要選取為基準**。一次對齊＝一個復原步驟。

**間距與置中**（WPF／BCB6 的「格式 → 水平間距 → 相等」「置於視窗中央」）：畫面右鍵「對齊與間距」子選單、屬性面板的多選區：

| 指令 | 做什麼 |
|---|---|
| 水平等距／垂直等距 | 選 **3 個以上**：最外面兩個不動，中間的平均分配，讓相鄰兩個的間隔都一樣 |
| 在容器中水平置中／垂直置中 | 一個或多個：整組當成一塊，放到所在容器（Panel、GroupBox、表單）的正中間，彼此的相對位置不變 |

這兩種**沒有基準元件**，主要選取也會動。選取裡有鎖定的元件，或位置不是寫在自己 style 裡的 px，就整個不做並在狀態列說原因（不會只動一半）。

**多選時改屬性**（WPF 屬性視窗的行為）：選了好幾個時，屬性面板「外觀與版面」改的值（字型、粗體、顏色、文字、Left／Width…）
會**套用到全部選取的元件**，一次＝一個復原步驟；面板上顯示的是主要選取的值。位置／大小是「全部或不做」：
其中有一個鎖定或不能改，就一個都不改並說原因。文字（Caption）只改有文字的那些。HTML 原始碼那一格只改主要選取。
**選取的元件值不一樣的欄位是空白的**（打勾的變成半勾，列名斜體），跟 WPF 一樣：例如三個 Label 字型大小不同，Font.Size 就是空的；
填一個值下去就三個都變成那個值。這些欄位不跟 DFM 比對。

**多選時的事件**（BCB6 Object Inspector／WinForms 的「事件」頁）：只列**選取的元件都有的事件**；處理函式不一樣的那一列是空白的、標「（不同）」。
在那一列打函式名稱＋Enter＝**全部接到同一個函式**（沒有就先在表單類別新增一次，再把每個元件的網頁連線、產生檔那一列接好）；
空白按 Enter 或雙擊＝全部接到預設名稱（主要選取的，例如 `spbSaveMouseUp`）；右鍵「重設（N 個全部）」＝每一個的連線都拿掉，C++ 函式留著。
多選時打名稱是「接上」不是「改名」。其中有一個是 BCB6 `.dfm` 指定的（golden 唯讀）或網頁 JS 自己送的，那一列唯讀——一個一個選來改。

滑鼠移到元件上，標籤會顯示 `名稱 : 型別 · 事件`，例如 `spbSave : TSpeedButton · OnClick   227×40`。

**HTML 的 style／屬性也能直接改**：屬性面板「HTML」區塊列的是**原始碼裡寫的** style 與屬性（不是瀏覽器展開後的一大串），
點一下值（或雙擊那一列）＝改，Enter 或離開欄位生效，清空＝刪掉那一項，Esc 取消；最下面「＋ 樣式名稱／值」可以新增一項（例如 `z-index`、`border`）。
屬性可以改 `title`、`class`、`placeholder`、`tabindex`、`alt`、`data-*`、`aria-*`；**id 不在這裡改**（網頁程式靠它找元件），`on…` 事件屬性也不行。
值裡不能有 `; { } < > \`（不能跑出那一項）。一樣寫回原始碼、一個 Ctrl+Z 復原。

**搜尋屬性**（WPF 屬性視窗上面那一格）：屬性面板標題下的搜尋框，打字就只留下符合的列 —— 所有區塊一起找
（可編輯的欄位連輸入框裡的值也算、事件、網頁監聽器、送到 C++ 的命令、資料欄位、DFM 屬性、HTML），
有找到的區塊自動展開、沒有的收起，旁邊顯示「找到 N 項」；空白隔開的多個字要同時符合（例如 `left 54`）。Esc 清掉。換元件時搜尋字會保留。

**在屬性面板改值**：面板最上面的「外觀與版面（可編輯）」，用 VCL 的屬性名稱：
`Left`、`Top`、`Width`、`Height`、`Caption`（輸入框是 `Text`）、`Visible`、`Enabled`、
`Font.Name`、`Font.Size`、`Font.Bold`、`Font.Italic`、`Font.Color`、`Color`。
表單本身（元件樹最上面那一個）可以改 `Width`／`Height`，跟 WPF 拉 Window 的大小一樣，但不能移動。
輸入後按 Enter 或離開欄位就生效（跟 WPF 的屬性視窗一樣），畫面和 HTML 原始碼同時改。Enter 之後游標留在那一格（值選好，可以直接打下一個值）；`Tab`＝跳到下一個屬性的值（右邊的小方塊、色塊、▾ 不會停）。
Label 還有 **`AutoSize`**（BCB6 一樣）：開著＝大小跟著文字（原始碼寫 `width:auto`），這時不能拉控制點改大小；
關掉＝寬高寫成它現在的大小（px），就可以拉了；再打開＝回到 auto。TLabel 在 .dfm 沒寫 AutoSize 就是 True（VCL 的預設）。
Label 的 **`Alignment`**（taLeftJustify／taCenter／taRightJustify ＝ 靠左／置中／靠右，寫成 `text-align`）也可以改、會跟 DFM 比對；
AutoSize 開著時寬度跟文字一樣，看不出對齊，要固定寬度才看得出來。
⚠ 網頁產生器沒有處理 Label 的 AutoSize=False 和 Alignment（例如 Setup.Contact 的 `labDelayStatus`：BCB6 是固定 273×25、文字置中，網頁是 width:auto、靠左）。
這種在差異清單會出現 AutoSize／Alignment 兩列；按「改回 DFM」會**直接用 DFM 的寬高**關掉 AutoSize、再加上對齊，一次就跟 BCB6 一樣。
**Panel** 也有 `Alignment`（寫在標題的 `span.pnlCap` 上；TPanel 沒寫就是置中）：網頁的 Panel 標題一律置中，DFM 是靠左／靠右的（例如 Data.Observer 的 `palCustomer`）會出現在差異清單。
`Font.Color`／`Color` 那一列是顏色框＋顏色值（可以直接打 `#rrggbb`、`#rgb` 或 `clRed`，按 Enter）；按後面的 **▾** 打開 BCB6 的 **16 個標準色**
（`clBlack` … `clWhite`，滑鼠停上去看名稱，點一下就套用）和**滴管**（點畫面上任何一點取色）。

**跟 DFM 比對、重設為 DFM 值**（WPF 的 property marker 和「重設」）：屬性表跟 WPF 一樣分三欄：名稱｜值｜最右邊的**小方塊**。
小方塊空心＝跟 BCB6 `.dfm` 的值一樣，實心＝不一樣，淡的＝不比對（DFM 沒寫這一項、系統色、多選時值不同）；**每一列都有**。滑鼠停在上面看 DFM 的值，點一下（或在那一列按右鍵）＝選單「重設（改回 DFM：…）」（一個復原步驟）和「跳到 HTML 原始碼」（同雙擊名稱）。
不一樣的那一列會標成警告色，值後面寫著 `DFM …`（一樣的列不寫，畫面乾淨）；比較長的說明（例如「執行時隱藏」）放在值後面的 **ⓘ**，滑鼠停上去看。
例如 `spbSave`：位置、大小、文字都跟 DFM 一樣；`Font.Size`（網頁 14、DFM 16）和 `Font.Bold` 不一樣，
因為網頁把存檔按鈕統一成一種樣式 —— **不一樣不代表錯**，網頁作者常常是刻意調的，要不要改回去由你決定。

- 只比 DFM **有寫的**屬性。DFM 沒寫（用預設值、或 `ParentFont`）的欄位不顯示 DFM 值，不去猜。
- `&Save` 的 `&` 是 VCL 的快捷鍵記號，比對時當成 `Save`。
- **原始碼沒寫的寬／高不比**：例如 `AutoSize` 的 Label，網頁沒給它 `width/height`，大小由文字決定；
  網頁的字型跟 BCB6 不一樣，大小本來就會差幾個 px（HotPlate 的 8 個 Label 全是這樣）。這時只顯示「DFM 136（大小由文字決定）」。
  兩邊都錨定（`left`＋`right`）的寬度算有寫。
- **系統色**（`clBtnFace`、`clWindowText`……）只顯示名稱、不比對：它的實際顏色看 Windows 佈景
  （同一個 `clBtnFace`，傳統佈景是 `#d4d0c8`、XP 佈景是 `#ece9d8`）。
- 字型：網頁的字型清單裡**有** DFM 的字型就算一樣（這些頁面刻意用 `"Microsoft JhengHei","MS Sans Serif"`，
  先用正黑體顯示中文）。元件**沒有自己的字型**、沿用表單 UI 字型的（網頁產生器對 Label／按鈕的做法），字型名稱不比。
- **字型大小照網頁產生器的換算**：`_gen_dfm_abs.py` 把 `Font.Height` −13 寫成 11px（|Height|−2）。
  所以 DFM 值顯示成「14（Height -16）」—— 14 才是「用這份 DFM 產生出來的頁面」會有的大小，↺ 也是改回 14。
- **Panel／GroupBox 的字型在標題上**：產生器把 TPanel 的 Font 寫在 `<span class="pnlCap">`、TGroupBox 的在 `<legend>`。
  屬性面板讀的、改的都是那裡（以前改 Panel 的字型大小會被 pnlCap 自己的 font-size 蓋掉，看不出效果）。
- **座標原點**：產生器會加外層包裝（例如 LED＋Label 合成的 `span.lled`），元件自己的 `left/top` 是相對包裝的。
  比對時會加回包裝的位移、換算成 DFM 的座標；↺ 寫回時再扣掉。分頁（`.pcPane`）就是 TabSheet，不算包裝。
- 實測全部頁面：位置／大小跟 DFM 一致的有 12,228 個、不一樣的 432 個（大多是網頁刻意移過的彈出面板）。

**頁面檢查**（WPF 的錯誤清單）：畫面右鍵「檢查與比對 → 檢查這一頁」，或「頁面」標題列的 ⚠「檢查所有頁面」。結果在 VS Code 的**「問題」面板**，
點一筆就跳到那一行；之後改那個檔，問題會自己更新。會找：
- **被引號切斷的屬性**（錯誤）：網頁產生器寫出 `style="…font-family:"MS Sans Serif",sans-serif;font-weight:400;"`，
  瀏覽器讀到 `font-family:` 就結束，字型和後面的東西（粗細…）全部被丟掉。實測 **21 頁、297 處**（Alert.Note 93、Setup.SCK_ART 54、HW.home 34…）。
  **修正**：在 HTML 原始碼裡按燈泡＝修這一處或整頁；設計畫面右鍵「檢查與比對 → 修正這一頁所有被切斷的屬性」。把裡面的 `"` 改成 `'`（本來的意思），一個 Ctrl+Z 復原、要存檔才寫入。
  ⚠ 這些是網頁作者的檔案，`sync_web.py --apply` 會蓋掉；根本的修法在產生器 `_gen_dfm_abs.py`（寫 `font-family:'…'`）。
- 同一頁 id 重複（錯誤）、有 id 的元素沒有結束標籤、`<img>`／`<script>`／`<link>` 用到的檔案不存在（警告）。
- **跟 BCB6 .dfm 不同**（等級「資訊」，不用打開設計檢視）：頁面標題寫了對應的 .dfm 時，逐一比對網頁產生器沒處理的屬性 ——
  Label 在 DFM 是 AutoSize=False 卻寫成 auto、固定寬度的 Label 對齊不同、Panel 標題的對齊不同。
  燈泡＝這一個改成 DFM 的寬高與對齊；「這一頁跟 DFM 不同的 Label／Panel 都改成 DFM 的」＝整頁一次（右鍵「檢查與比對」也有）。
  這些是資訊不是錯誤：「頁面」清單的 ⚠ 數字不算它們。不想看到可以關掉設定 `ht9045Designer.lintDfmGaps`。
- 檢查過的頁面在左邊「頁面」清單會顯示問題數（例如 `⚠ 93`），分組也有合計；清單上每一頁按右鍵也有「檢查這一頁」（不用先打開）。

**在畫面上標出接線狀態**（畫面右鍵「顯示」，或命令「HTML設計: 在畫面上標出接線狀態」）：DFM 裡有事件的元件加上彩色框 ——
**綠**＝網頁都接了（有監聽器，或由 wire 引擎的欄位對照處理）、**橘**＝只接了一部分或只有提到（多半是事件委派）、**紅**＝網頁完全沒接。
右下角有顏色說明，狀態列顯示「接線標示」；再按一次關掉。資料跟「接線總覽」同一份，所以哪個紅了就去總覽或屬性面板看細節。
做 BCB6 → 網頁移植時，一眼就看得出這一頁還有哪些按鈕沒接。

**顯示 Tab 順序**（BCB6 的「Edit → Tab Order」、WinForms 的「檢視 → Tab 鍵順序」；畫面右鍵「顯示」或命令「HTML設計: 顯示 Tab 順序」）：
網頁上每個按 Tab 會停的地方貼一個小圓標，照網頁真正的 Tab 順序編號，並跟 `.dfm` 的 TabOrder 比對
（照 VCL 的規則：每個容器裡依 TabOrder、先走完一個容器裡面再到下一個；TabStop=False、Label 之類、看不到或停用的不算）：

| 標記 | 意思 |
|---|---|
| 藍 `3` | 第 3 個，跟 DFM 一樣 |
| 紅 `3≠5` | 網頁是第 3 個、DFM 裡是第 5 個（只算兩邊都有的元件） |
| 灰 `·` | 網頁會停，但 DFM 沒有這個停點（例如 TSpeedButton 在網頁變成 `<button>`） |

狀態列說有幾個順序不同，清單寫在輸出面板「HTML 視覺設計」。操作員在設定頁用鍵盤一格一格輸入數值時，這個順序就是 Tab 鍵跳的順序。

**整頁「與 DFM 的差異」**：分頁標題列的差異圖示按鈕、畫面右鍵「檢查與比對」、或命令「HTML設計: 與 DFM 的差異」。
一次列出這一頁**所有**跟 `.dfm` 不一樣的屬性：元件、屬性、網頁的值、DFM 的值。

- 上面可以只看「位置／大小」「文字」「外觀」，也可以打字篩選。
- **同一種差異收成一行**：同一型別至少 5 個元件都有一模一樣的差異（例如 IoSetView 的 612 個 TBtnPanelLane 都是粗體、
  DFM 不是），多半是網頁的統一樣式，收在「同一種差異」裡，一種一行、附個數；點那一行才列出是哪些元件。
  清單本身預設只列**個別差異**（IoSetView：3,348 項 → 個別 92 項＋同一種差異 13 種）。
  外觀／文字類的「同一種差異」那一行有 **「全部改回」**：會先問，然後那幾個元件一次改回 DFM 的值 —— **一個 Ctrl+Z 全部復原**。
  位置／大小類沒有這個按鈕（每個元件的 DFM 值都不一樣，一個一個看比較安全）。
- **改回 DFM（選取的元件）**：畫面右鍵「改回 DFM」、屬性面板差異說明後面的「這個元件全部改回 DFM」（多選時是「全部改回 DFM（N 個）」）：
  選取的每個元件的**位置、大小、文字、外觀**一次改回它自己在 `.dfm` 的值，**一個 Ctrl+Z 全部復原**。鎖定的元件位置不動（狀態列會說）。
- 點一列＝在畫面上選取那個元件；按 **↺**＝只把那一項改回 DFM 的值（一次一項，Ctrl+Z 可以復原）。個別差異沒有「全部改回」—— 一項一項看過再決定（只有「同一種差異」才有）。
- **在畫面上畫出 DFM 位置**（清單上方的按鈕、畫面右鍵「顯示」、或命令「HTML設計: 在畫面上畫出 DFM 的位置」）：
  位置／大小跟 `.dfm` 不一樣的元件，在設計畫面上用**紫色虛線框**畫出 BCB6 原本的位置；選到的那個框比較粗，下面寫著 DFM 的 left／top／大小。
  框固定在 DFM 的位置，**把元件拖過去會吸附上去**（放上去就跟 DFM 一樣了）。改完之後框會自己重新比對；狀態列顯示「DFM 位置」，再按一次關掉。
- 改完、復原、或頁面重畫之後，清單會自己重新比對；在別處改過頁面的話按「重新比對」。
- 標 `*` 的是目前**沒有顯示**的元件（在沒切到的分頁、或隱藏的面板裡）：畫面量不到它的大小，改用原始碼 `style` 裡寫的數值比對。
- 頁面 JS 產生的元件（HTML 原始碼裡沒有）↺ 是灰的：沒有地方可以寫回去。

**改到哪裡**：跟 WPF 改 XAML 一樣，改的是這一頁的 **HTML 原始碼**，而且只動被改到的那一小段：

- 位置／大小：元件自己標籤的 `style` 裡的 `left/top/width/height`（或 `right/bottom`，看它原本怎麼錨定）。
  兩邊都錨定的元件（例如 `left:121px; right:0px` 沒有 `width`）：移動時兩邊一起動、大小不變；改大小時只動遠的那一邊。
  輸入框（`<input>`）的位置由外面那層 `<span style="position:absolute…">` 決定，所以改的是那層。
- 文字：按鈕／標籤的文字、GroupBox 的 `<legend>`、Panel 的標題、輸入框的 `value`。
- Visible＝`display:none`、Enabled＝`disabled`、字型大小／顏色＝`style`。
- 分頁標題會顯示「未存檔」，**按 Ctrl+S 才寫到磁碟**。旁邊開著 HTML 原始碼的話會即時看到它被改。
- 復原／重做：Ctrl+Z／Ctrl+Y，或設計畫面標題列的 ↶ ↷ 兩個按鈕。

**Visual Studio 的快捷鍵**：F4＝跳到屬性面板、Ctrl+Alt+X＝跳到工具箱、Ctrl+Alt+T＝跳到元件樹（文件大綱）。

**設計時全部顯示、執行時才決定**（跟 BCB6／WinForms 的表單設計畫面一樣）：設計模式下**所有元件、所有頁籤都畫出來**，

**要不要隱藏是屬性**：屬性面板的 **Visible** 勾掉＝寫進 HTML（`display:none`），**執行時才隱藏**，設計畫面上照樣看得到，

## CSV 表格

打開 `.csv`（例如 `D:\HT9045\system\Mot_Table.csv`）就是像 Excel 的表格：點格子直接打字（注音等中文輸入法也可以）、雙擊或 F2 編輯、Enter／Tab／方向鍵移動、
Shift＋方向鍵選一塊、Delete 清除、`Ctrl+C`／`Ctrl+V` 跟 Excel 互相複製貼上（Tab 分隔）、插入／刪除列、尋找（`Ctrl+F`）、
第一列固定當標題（自動判斷，可以勾掉）、拉欄名右邊的線改欄寬。幾萬列的檔也順（只畫看得到的列）。
照 Excel 的規則（0.123 起，對照 Excel 官方說明）：作用中的那一格是選取的起點；選好範圍打值按 `Ctrl+Enter`＝每格都填，`Ctrl+D`／`Ctrl+R` 往下／往右填，
複製一格貼到一整欄＝整欄都填；`Ctrl+X` 剪下是貼上時才搬；`Shift+空白鍵`／`Ctrl+空白鍵` 選整列／整欄；`Ctrl+－` 只刪整列；`Ctrl+H` 取代；
最後一列下面有一列空白可以直接打字新增；狀態列顯示這一列的前兩欄（是哪一軸）和選取數字的加總／最小／最大。
**右鍵選單**（Excel 的儲存格選單，0.132 起）：剪下／複製／貼上、插入／刪除列、清除內容、選取整列／整欄、尋找／取代，每一項後面寫著它的快捷鍵；
在選取範圍裡按右鍵＝範圍不變，範圍外＝改選那一格（在選取的列號／欄名上按也一樣）；`Shift+F10` 或選單鍵＝在作用中的格子打開；
上下鍵＋Enter 選、Esc 關。唯讀的檔，會改到檔案的項目是灰的。
**名稱方塊**（Excel，0.133 起）：工具列最左邊顯示目前的格子（例如 `B3`）；`Ctrl+G` 或點它，打 `C12`、`B2:D5` 或列號 `12` 再按 Enter＝跳過去並選取
（表格沒有的位置會說，不會動）。**雙擊欄名右邊的線＝自動調整欄寬**（照那一欄最長的值；選了整欄再雙擊其中一條＝每一欄都調）。
`F5` 留給 VS Code（開始偵錯），不是 Excel 的「到」。

**只改你改的那幾格的文字**：其他的換行（CRLF）、引號、行尾空的欄位一個字都不動 —— 機台的設定檔就是 CSV，
不能被「整檔重寫」。改的東西進 VS Code 的編輯緩衝區，**按 `Ctrl+S` 才存檔**，`Ctrl+Z` 復原。
值裡有逗號、引號、換行時自動加引號；原本有引號的格子改完還是有引號。

⚠ **Big5 的檔**：VS Code 預設用 UTF-8 讀，中文變成 �。這種檔只能看、不能改（存檔會把中文毀掉），
畫面上方會說：按右下角「UTF-8」→「以編碼重新開啟」→「Traditional Chinese (Big5)」之後就能改。
要看原始文字：表格右上「以文字開啟」；文字編輯器的標題列有表格圖示可以切回來（檔案總管右鍵也有「以表格開啟」）。

## 事件會跳到哪裡

同一個按鈕的程式碼在這個專案裡有三份，面板用顏色標籤區分：

| 標籤 | 位置 | 怎麼找到的 |
|---|---|---|
| **網頁** | `web\page\*.js`、頁面內的 `<script>` | 預覽時記錄頁面真的綁了哪些監聽器，再用函式原文找到它寫在哪一行。**這是瀏覽器按下去實際執行的程式** |
| **C++** | 移植樹 `HT9011UC_Cpp_*` | 搜尋 `TfXxx::事件名`。會標出「定義」「在 `#if 0` 裡（不會編譯）」「註解提到（實作可能搬到這裡）」 |
| **BCB6** | golden `HT9011UC_Code_V*` | 搜尋 `TfXxx::事件名`。**用 Big5 解碼、唯讀開啟**，不可能被存成 UTF-8 |

另外，如果網頁的處理函式會送命令給 C++，事件清單也會列出那個命令在 C++ 伺服器的處理位置
（標成「網頁命令 x.y → …」）。**網頁上按下按鈕，實際在機台上跑的就是這一段**；
`TfXxx::事件名` 是 BCB6 表單翻譯過來的版本，網頁不一定會走到它。

設定 `ht9045Designer.eventJump` 可以改成固定優先跳某一份（`web`／`cpp`／`golden`），不再每次問。

## 安全設計

這台是實際機台的控制電腦，所以外掛從設計上就不可能動到機台：

1. **預覽畫面沒有網路。** 頁面前面加了一道 Content-Security-Policy，只允許讀取本機的網頁檔案。
   WebSocket、HTTP、內嵌 iframe、表單送出全部被瀏覽器擋掉，
   **連不到 `wb_gateway`／`wb_serve`（8045／8046），也連不到任何其他地方**。
   實測：HotPlate 頁自己的通訊層試圖連 `ws://ht9045/`，被擋下了。
2. **設計模式下，頁面的點擊處理不會執行。** 點擊在最外層就被攔下，只拿來選取元件。
   只有切到「操作模式」才會交給頁面（Ctrl＋點／Ctrl＋拖曳是多選和複製，頁面一樣收不到），而那時網路仍然是封死的。
3. **外掛自己不寫任何檔案。** 設計畫面上的修改只進 VS Code 的編輯緩衝區（跟打字一樣），要你按 Ctrl+S 才會存檔；
   除此之外只讀 HTML、JS、`tools\dfm2rc\ir_out\*.json` 和兩棵原始碼樹。
4. **golden 樹唯讀。** BCB6 原始碼透過外掛自己的**唯讀檔案系統**開啟：編輯器不能打字，任何寫入都會被拒絕（`NoPermissions`），
   所以不可能被存回成 UTF-8。

5. **機種與機台設定只讀不寫。** 有些頁面是問伺服器「這台是什麼機種」「機台設定是什麼」才決定顯示哪些東西
   （例如 IO 頁面的 **Above9050** 頁籤）。設計檢視沒有網路，所以改成：機種用 **F5 開機台畫面時的同一個**
   （`.vscode/launch.json` 的 `W906_HMI_URL` 裡的 `machine=`），機台設定讀 F5 給 wb_serve 的檔案
   （`W906_GENERAL_INI_PATH` 的 Gerneral.ini、`W906_AUTH_PATH` 的 config.ini），**只用 Node 讀檔，從來不寫**，
   格式跟 wb_serve 的 `/api/system/gerneral` 一樣。頁面只拿得到這兩份的 **GET**；其他連線照樣全部擋掉。
   右鍵「顯示」→「設計檢視的機種…」可以改成 HT9045／HT9050，或「不指定」（跟沒有伺服器時一樣，也不讀設定檔）；
   設定 `ht9045Designer.generalIni`／`configIni` 可以指定別的檔。狀態列會寫目前的機種。

面板最下面會列出這一頁被擋下的連線，輸出面板「HTML 視覺設計」有完整紀錄。
想自己確認：`Ctrl+Shift+P` →「HTML設計: 檢查預覽畫面的網路封鎖」，會從頁面裡面試連 WebSocket／HTTP／XHR
（對象是 `127.0.0.1:9` 這個關閉的埠，不是機台），並回報是否全部被擋下。

實測 20260929（真正的 VS Code 1.139）：`main.html`、`HW.MotorTest.html`、`Setup.Speed.html`、`Data.LotInfo.html`、
`Status.Security.html` 在預覽裡都試圖連 `ws://…/ht9045`（通訊閘道），**全部被擋下**。

## 已知限制

- **只改得動寫在元件自己 `style` 裡的 px 數值**。位置是 `%`、`auto` 或寫在 CSS class 裡的元件，會拒絕修改並在狀態列說明，不會亂猜。
- **頁面 JS 產生的元件**（例如 `HW.IoSetView.html` 的清單）HTML 原始碼裡沒有，不能改；面板會寫明原因。
- **HTML 會被同步覆蓋**：見上面「改到哪裡」的 ⚠。DFM 屬性（BCB6 的 Object Inspector 那份）是參考資料，只能看。
- 新增、刪除、複製貼上元件都可以，但這些頁面是照 BCB6 表單做的，元件增減最好也跟網頁作者講（`sync_web.py --apply` 會蓋掉）。
- **80 頁裡 44 頁的標題寫明對應哪個 DFM**；其他頁用元件名稱推測，推測不到就只顯示 HTML 屬性和網頁 JS。
- **只在連線成功後才綁的監聽器看不到**，因為預覽不連線。「網頁 JS 提到此元件」那一段是靠搜尋，可以補一部分。
- **C++ 的 `#if 0` 判斷是靜態掃描**，只認得 `#if 0`／`#if 1`；`#ifdef SOFT_SIMULTE` 這類要看建置線的，一律當成活的。
  要確定某一行有沒有被編譯，用 `tools\live_lines.ps1`。
- **命令追蹤是靜態的**：命令名稱是字串接出來的（`cmd(prefix + '.put')`）就追不到；同名函式在好幾個檔都有時，
  先用同一個檔裡的，沒有才去別的檔找。
- **內嵌 iframe 不載入**（為了不繞過網路封鎖）。目前只有 `IDE.MotionView9050-UPH.html` 有 iframe。
- **轉址頁**（例如 `Setup.BinSelNormal.html` 只有 `location.replace('Setup.BinSel.html')`）不會真的跳走，
  設計檢視會寫「這頁只會轉到 …」，並給一個按鈕用設計檢視開目標頁。
- **靠 JS 在執行期畫出來的頁面**（例如 `HW.IoSetView.html` 的清單）要等 JS 跑完才看得到；它讀的是本機 `JSON\` 檔，這個讀得到。

## 檔案

| 檔案 | 用途 |
|---|---|
| `extension.js` | 外掛主程式：設計檢視分頁、元件樹、屬性面板、跳到程式碼 |
| `media/probe.js` | 注入頁面的探針：選取、攔點擊、記錄監聽器 |

| `media/overview.js`、`overview.css`、`lib/overview.js` | 接線總覽 |

| `lib/pageinfo.js` | 頁面對應哪個 DFM、讀 IR |
| `lib/cppindex.js`、`cpplex.js` | 搜尋 C++／BCB6 的 `Class::方法`，判斷註解與 `#if 0` |

| `lib/format.js` | DFM 屬性格式化（TColor 等）、VCL 事件對應的 DOM 事件 |

| `lib/webcmds.js` | 反查：命令字串 → 網頁哪裡送出；設定欄位 → 哪個元件在編輯它；資料標籤 → 哪個元件在顯示它 |
| `pack.ps1` | 打包成 `.vsix` |
