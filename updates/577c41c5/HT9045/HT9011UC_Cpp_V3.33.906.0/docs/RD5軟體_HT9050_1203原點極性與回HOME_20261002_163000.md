## 1. 這次改了什麼（`AI(W906-HT9050-ORG-ST)` 20261002）

**使用者 1002 16:1x 指示**：HT9050（GPIB `general.ini` 的 `Model=9050GPIB`）的 1203 軸，原點判斷「照該軸 Mot_Table `SensorType` 決定」，像 SMC 一樣改表就能換邊。

| | 改之前（`AI(W906-HT9050-ORG)` 20261001） | 改之後 |
|---|---|---|
| 規則 | 所有 1203 軸一律「ORG 位元 0（low）＝在原點」，不看 SensorType | **逐軸**：`SensorType=1` ⇒ low＝在原點；`SensorType=0` ⇒ high＝在原點（跟 golden `InitMotor` `uOrgLogic = bSensorType ? ORG_ACT_LOW : ORG_ACT_HIGH` 同一個意思） |
| 判斷（Teach 的「Z 在原點」檢查、引擎 `Led[iHomeLed]`、回原點 case 20、`uhome.cpp` InArmX 檢查） | `WebMotorAccess.cpp` `MotorAccessTeachHomeLed` | 同一支，改成逐軸 |
| 顯示（Motor Test／Motor View 的 HOME 燈） | `JsonBridge/ChanMotorPoints.cpp` `led.home` | 同一條規則（純顯示） |
| `machines/HT9050/Mot_Table.csv` | — | 20261002 晚上換成**機台正本**（機台推上 GitHub 的快照，見 `machines/HT9050/README.md`）。⚠ 初版（1002 16:xx）在 repo 那一份把 10 列 SensorType 0→1，但那一份是 0928 的舊檔，列表跟機台對不上，已被機台正本取代 |

### ⚠ 套用時一定要做

1. **機台自己的 `system\Mot_Table.csv`：凡 `CardModel=PCI1203` 而且 `Enable=1`、SensorType 是 0 的列，改成 1**（先備份）。照機台 1002 19:29 的快照是這 **16 列**：M11 MInShuttle1、M14 MTestZ1、M17 MOutShuttle1、M18 MOutShuttle2、M19 MOutArmX、M20 MOutArmY、M22 MOutArmZA、M30 MTrayX、M35 MLoaderZ、M36 MEmptyZ、M38 MAuto1Z、M39 MAuto2Z、M40 MAuto3Z、M41 MInRotate、M42 MOutRotate、M108 MCCDY（M00 MInArmX、M01 MInArmY、M03 MInArmZA 已經是 1）。
   ⚠ 20261002 晚更正：初版寫的「10 列」是照 repo 的舊檔算的，**以本條為準**；機台的檔之後若又改過，以機台實際的檔為準。
   沒改的話，SensorType＝0 的軸會被判成「high＝在原點」，跟現在相反：Teach 的 Z 檢查會擋錯，回原點會等不到「到原點」。
2. **之後要哪一軸反過來，就只改那一軸的 SensorType**（0↔1），重開 wb_serve 生效。

### ⚠ 一個還沒量過的前提

- SensorType 也會寫進卡片的 `CFG_AxOrgLogic`（golden `Motor/myEthercatmotor.cpp:492`），但**不是開機就寫**：只有 Motor Test 按 **Test Range／Test Rate**（golden `btnSetRangeClick`／`btnSetRateClick` → `InitMotor`，`WebMotorAccess.cpp` `InitMotor1203`、`EtherCAT/Pci1203Control.cpp` `Pci1203GoldenInitCfgPlan`）時才寫；機台 cpp 0132（BOOT-INITMOTOR，1002 18:35）另外讓 M35 MLoaderZ 開機時跑一次。引擎馬達路由（`WB_ENGINE_MOTOR_1203`）目前關著，不會寫。
- 本規則假設卡片**不會**再依 OrgLogic 把 motionIO bit 4 反相，也就是 bit 4 是 /Home 的原始準位。
- ⚠ 20261002 晚更正：初版寫的「證據」（EastSun 1001 看到 MInArmX SensorType=1、Y／ZA=0 都是 low＝偵測到）**不成立**——那幾軸沒按過 Test Range／Test Rate 的話，卡片根本沒收到 SensorType，兩邊一樣是預期的（機台 cpp 0132 的說明也寫「SensorType / In1Logic never reached the card」）。這個前提目前**沒有證據**，只能上機量。
- **上機確認法**：改完 Mot_Table、重開 wb_serve 後，挑一軸 SensorType 從 0 改成 1 的軸（例 M22 MOutArmZA；MInArmY 在機台上本來就是 1，不能用）。**先在 Motor Test 對它按一次 Test Range（或 Test Rate）**，讓新的 SensorType 寫進卡片（Test Range 照 golden 重新初始化該軸：會 Servo ON、HomeFlag 清成 0，量完要重新回原點；機台旁要有人），再遮住 sensor ⇒ HOME 燈要亮；放開 ⇒ 燈要滅。結果相反就代表卡片會依 OrgLogic 反相，請先把 Mot_Table 改回並回報（量法也在 `docs/W5_PROGRESS.md` Q2）。

## 2. Mot_Table 的三個極性欄位（1203）

| 欄位 | 管什麼 | 程式 |
|---|---|---|
| `SensorType` | 原點（ORG）極性：1＝low 有效、0＝high 有效 | 卡片 `CFG_AxOrgLogic`（`myEthercatmotor.cpp:492`）；HT9050 分支的原點判斷（本次） |
| `LimitLogic` | 極限開關極性（其他卡用） | **1203 這條路不讀它**（`Motor/myEthercatmotor.cpp` 沒有用到 `bLimitLogic`）；1203 的極限極性由 **`D:\HT9045\config\Pci1203Axis.ini`**（路徑寫死在 `EtherCAT/Pci1203Control.cpp:109`）的 `pelLogic`／`melLogic` 設，以 `[station<站號>.axis<子軸>]` 分區；1203 監看頁設定時寫回（`:142`），開機後逐項套用到卡片（`Pci1203AxisIniTick`）。`machines/HT9050/Pci1203Axis.ini` 只是 repo 裡的存檔，程式不讀 |
| `In1Logic` | **伺服警報（ALM）極性**，不是原點 | `CFG_AxAlmLogic = bIn1Logic ? 0 : 1`（`myEthercatmotor.cpp:2016`）。⚠ `docs/HAL_MOTTABLE_CLASSIFICATION.md:87` 寫成「IN1 近原點」是錯的 |

Advantech 定義：`ORG_ACT_LOW=0`、`ORG_ACT_HIGH=1`（`EtherCAT/vendor/AdvMotDrv.h:729-730`）。

## 3. 原點訊號怎麼讀、怎麼看

```
驅動器（安川 Σ-X）的 /Home 輸入 → 60FDh bit 2（套過驅動器 Pn511 的極性）
  → 1203 卡 Acm_AxGetMotionIO 的 AX_MOTION_IO_ORG（bit 4，0x10）
  → 監看器 EtherCAT/Pci1203Monitor.cpp:2330-2366（每輪每軸讀 state／motionIO／位置／速度，五個都成功才算數）
  → tag pci1203.ax<N>.motionIO 與 pci1203.ax<N>.org（WebBridgeTags.cpp:1713、:1955-1993）
  → 1203 監看頁 web/pci1203.html（ORG 燈、motionIO 十六進位）
  → 判斷：WebMotorAccess.cpp MotorAccessTeachHomeLed；顯示：ChanMotorPoints.cpp led.home
```

**在機台上看**：1203 監看頁找到該軸，遮住／放開 sensor 各看一次 ORG 燈（bit 4）。
- 會變：照該軸 SensorType 對一下是不是想要的極性。
- 完全不變：可能 sensor 接在 IO 模組而不是驅動器的原點輸入；或 ring 的循環通訊停了（同頁極限、DI 燈也全不動）。0911 的「整條 ring 凍住」原因是讀 ESC 暫存器，已預設關掉（`Pci1203Monitor.cpp:1270-1300`）。

## 4. 回 HOME 流程（依 SDK 與本樹程式）

### 4.1 SDK 有兩種歸零

| | 卡片做（Advantech「典型」16 種） | 驅動器做（CiA402 / DS402） |
|---|---|---|
| 呼叫 | `Acm_AxMoveHome(MODE1..16, dir)` | `Acm_AxHome(101..137, dir)`＝CiA402 方法 1～37＋100（`docs/RECON_PCIE1203_CommonMotion.md` §3） |
| 誰產生運動 | 卡片 | 驅動器 |
| 參數 | 卡片的 `PAR_AxHomeVel*`／`Acc`／`Dec`、`CFG_AxOrgLogic` | 驅動器物件 `6098h`（方法）、`6099h:1`／`:2`（找開關／找零點速度）、`609Ah`（加速）、`607Ch`（原點偏移） |
| 原廠範例 | `Examples_EtherCAT\Windows\C#\Home\Form1.cs`（ORG Low／High 選鈕 `:409-427`） | 同一支 `SetHomeParams` 用 `mAcm_DevWriteSDOData` 寫 `6098h`／`6099h`／`609Ah`（`:1090-1150`） |
| HT9050 | **不能用**：這台的軸回 `0x8000510F` | **用這個**：方法 24／28（`WebMotorAccess.cpp:1239-1240`、`:1363`） |

### 4.2 本樹按下 HOME 之後（`WebMotorAccess.cpp` `StartHome1203` `:1300-1375`）

1. `HomeFlag=0`（golden 一按就清）。
2. 安全門開著 ⇒ 拒絕（golden `TMyMotor::Home` 的 `CheckIsSafeDoorOpen`）。
3. 監看器樣本太舊 ⇒ 拒絕。
4. 判斷驅動器類型：DS402 ⇒ 下面這條；不是 DS402 ⇒ 走 golden 的卡片式 MODE12（`StartHomeCardSide`）；判斷不出 ⇒ 拒絕（不猜）。
5. `Home High Speed` 是 0 ⇒ 拒絕。
6. 寫卡片歸零速度（照原廠範例與 golden `SetHomeSpeed`），再把**卡片的 PTP 速度設成歸零速度**。原因：實測 `Acm_AxHome` 在呼叫當下，拿卡片 PTP 的 VelHigh／VelLow／Acc 去填驅動器 `6099h:1`／`:2`／`609Ah`（`EtherCAT/Pci1203Gear.h:470-510`，0917 量到），不讀卡片的歸零速度。
7. `Acm_AxHome(HomeDirectior ? 124 : 128, HomeDirectior ? +1 : -1)`。
8. 驅動器做完後，Z 軸照 golden case 500 移到 `ZSafePos` 才算 `HomeFlag=1`。

### 4.3 哪些可以用軟體設定

| 項目 | 現在由誰決定 | 能不能用軟體設 |
|---|---|---|
| 歸零方法 | 程式固定 24／28 | 換方向：可以（下一列）；換成別的方法：要改程式 |
| 起跑方向 | Mot_Table `HomeDirectior`（1⇒124／+1，0⇒128／−1） | **可以** |
| 找開關／找零點速度 | Mot_Table `HomeHighSpeed`／`HomeLowSpeed` ⇒ 經 PTP 速度填進 `6099h:1`／`:2` | **可以** |
| 加減速 | Mot_Table `Acc`／`Dec` ⇒ `609Ah` | **可以** |
| 原點偏移 `607Ch` | 驅動器（卡片不寫它） | **可以**：1203 監看頁的驅動器歸零參數（找開關速度／找零點速度／歸原點加速度／原點偏移量，`web/js/pci1203/view.js:3235-3241`，命令 `pci1203.ax.setDriveHome`）。`607Ch` 寫了會留著；另外三個下次歸零會被 PTP 速度蓋掉（上面第 6 步） |
| **原點開關極性（a／b 接點）** | **驅動器 `Pn511`**（XS：4／5／6＝CN1-10／11／12 ON 有效，D／E／F＝OFF 有效；`60FDh bit 2`＝/Home 狀態；`docs/WORKLOG_MACHINE.md:62`） | **目前軟體不寫**。用 SigmaWin+ 設；要程式寫，得 EastSun 把物件加進 SDO 寫入白名單，而且可能要重新上電 |
| 歸零後 Z 的位置 | `Gerneral.ini` `ZSafePos` | 可以 |

### 4.4 ⚠ 原點極性有兩層，要一起決定

- **驅動器 `Pn511`** 決定驅動器歸零時把哪個準位當成「在開關上」，也就是歸零動作本身。
- **軟體的 SensorType 規則**（第 1 節）決定程式和畫面怎麼解讀 bit 4。
- 如果把某軸的 `Pn511` 改成 OFF 有效，`60FDh bit 2`（bit 4）會變成「1＝在原點」。這時那一軸的 SensorType 也要改成 0，否則判斷會反過來。
