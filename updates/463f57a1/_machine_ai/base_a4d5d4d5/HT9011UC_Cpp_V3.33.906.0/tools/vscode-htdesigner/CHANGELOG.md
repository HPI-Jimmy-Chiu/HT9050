# 更新紀錄

每一版多了什麼。怎麼操作看 [操作一覽](CHEATSHEET.md)，詳細說明看 README。

## 0.228.0
- **屬性面板：改回原本的值，原始碼也會回到原樣**（agent 對 82 頁、19,249 個元件、428,056 個屬性列逐一改了再改回）。以前字型、粗體、斜體、顏色、背景改回去時，會寫出原本沒有的 `font-style:normal`、`color:#222222`（約 95,000 筆）。現在設回「跟沒設一樣」的值會直接拿掉那個宣告；值意思相同時照原始碼原本的寫法（`#000` 不會變 `#000000`，`400` 不會變 `normal`）。
- **嚴重：HTML 區的屬性表格，按 Enter 會把 `&quot;` 寫成 `&amp;quot;`，弄壞 tray 的設定（data-tray JSON）**。現在表格顯示的是解碼後的值，寫回時再編碼一次。
- **表單多加一個 class 後，表單所有屬性都改不了**（「找不到 id=@form」），已修。
- **顏色可以清回「不設定」**：#rrggbb 框清空再按 Enter。以前沒辦法，送空值還會寫出 `background-color:;`。
- 可見、底線、刪除線關了再開，不會再留下空的 `style=""`；沒有結尾分號的 style 也不會多出分號。
- 產生器寫的 `width:136px;…;width:auto` 這種重複宣告會保留：AutoSize 關了再開不會遺失原本的寬高；HTML 區的樣式表格只列實際生效的那一個。
- 文字（Caption）顯示原始碼裡的文字，不是頁面 JS 執行後改過的文字（以前改回去會把 JS 的文字寫進原始碼）。
- 原本沒有任何提示的拒絕現在都會說原因：圖片來源用 `javascript:`、不是絕對定位的標籤切換 AutoSize。分頁（TTabSheet）的灰色提示不再誤說「頁面 JS 產生的」。
## 0.227.0
- **嚴重：GroupBox 裡的第一個元件，刪除／剪下／拖曳會連同旁邊的元件一起帶走**（agent 檢查工具箱與結構操作找到的，30 多頁、974 個元件）。例如 Setup.HotPlate 刪 Image1 會連 Image2、cbEnableHP1、cbEnableHP2 一起刪掉。原因是把 GroupBox 的內容區 `div.cli` 誤當成那個元件的外框。現在只有「裡面只包這個元件」的外框才算（帶標籤的 LED 照舊整組）。這也一併解決了「放進群組」被拒絕、在元件樹拖曳被說成「放進它自己裡面」等問題。
- **放進 GroupBox 不會再讓元件往左上偏 2px**，解除群組也回得到原位（頁面的 GroupBox 沒有邊框，以前卻扣了 2px 邊框）。
- **新增、貼上、移動、解除群組改用頁面自己的換行（CRLF）**：以前寫入的是 LF，頁面變成混合換行，貼上後再刪除也不會跟原本一模一樣。
- **複製的元件不再連到原本的**：選項按鈕的群組（name）、list、data-* 參照、PageControl 的分頁名稱都會跟著改名。以前複製一組選項按鈕，按複製品會把原本那組的選取清掉；複製的 PageControl 新增元件會跑到原本那個裡面。
- **剪下再貼上會保留原本的名稱和位置**（跟 C++Builder／WPF 一樣），以前一定改名又往右下偏 8px。
- **一次刪除相鄰的幾個元件不會再被拒絕**（以前常說「同一段原始碼被改了兩次（重疊）」）；在元件樹拖到緊鄰的前一個元件上，會說「已經在它後面了」而不是報錯。
- **寫成 `<input>` 的 TPanel（Data.StartCondition 的 PanelAa～PanelDh）不再被當成容器**：以前選它再新增、貼上、拖放、釘選都會失敗並顯示誤導的訊息。
- 輸入框的定位外框和輸入框之間夾了註解時，也認得那個外框（以前刪除會留下空的外框）。
- 工具箱連點兩下新增後，下一次點「指標」不會再誤說「放下拿起的工具」。
## 0.226.0
- **舊版 ▶（設定 run.likeF5 = false）：不會先把東西停掉再拒絕啟動**（執行列 E7）：以前先停掉正在跑的程式，才發現另一個建置在跑／沒有啟動設定／偵錯器選了取消，結果什麼都沒在跑。現在檢查都過了才停。
- **Release（不接偵錯器）啟動不會再誤報「程式沒有跑起來」**（E6）：不接偵錯器時 VS Code 會馬上結束工作階段，但 wb_serve 其實還在跑；現在先確認程式在不在才報錯。
## 0.225.0
- **F5 等舊程式正常關站時（最多 30 秒），▶ 會變灰**（執行列 E3）：以前那段時間 ▶ 還能按，會再啟動一次。
- launch.json／settings.json 讀取時，字串裡的「, ]」「, }」不會再被當成多餘的逗號刪掉（L4）。
## 0.224.0
- **⏹ 停止後會確認程式真的結束了**（執行列 agent S6）：以前強制結束後不檢查就說「已全部停止」。現在會再看一次，還在跑的會列出名稱和 PID 並警告（可能權限不夠或卡在驅動程式裡），⏹ 也維持亮著。
- **只有真正的建置工作才會被當成「建置中」**（E2）：以前任何名稱或設定裡有 build 字樣的工作（例如網頁的 build:css）都會蓋掉建置進度列和 F5 的建置狀態。現在只認「建置」群組、名稱有 建置／編譯／cmake，或命令是這棵樹的 build*.bat／cmake；組合工作（等待畫面 + build）不再被誤認（B5 的一部分）。
- **視窗在背景時，檢查程式是否在跑的頻率從 3 秒降到 15 秒**（P1），省下多開視窗時一直跑的 tasklist。
## 0.223.0
- **寫壞的正規式不會再讓整個 VS Code 卡死**（搜尋 agent 第 5 項）：像 `(a+)+$` 這種會無限回溯的式子，碰到某些行會在一次比對裡跑好幾分鐘，以前整個視窗凍住、按「取消」也沒用。現在搜尋在背景執行緒跑，取消後 1 秒內沒停就強制結束，並提示可能是正規式的問題。
## 0.222.0
- **專案搜尋的「取代」在混合換行的檔案會換到旁邊的字**（agent 檢查搜尋功能找到的）：以前用讀檔時的位置去換，而編輯器裡的文字換行只有一種，所以檔案裡 CRLF／LF 混在一起時位置會偏。現在按「第幾行、第幾欄」在編輯器的文字裡重新確認那一筆再換。
- **正規式取代支援前後查找（lookaround）和 ^ $**：以前把那一筆單獨切出來比對，`(?<=…)`、`(?=…)` 這類一律被當成「檔案已經改過」而略過。現在在整段文字原地比對；`$1`、`$<名稱>`、`$&`、`$$` 都照 VS Code 的規則填。
- **正規式的 ^ 和 $ 現在是「行首／行尾」**（跟 Visual Studio 一樣），以前是整個檔案的開頭和結尾。
- **點一筆結果會選到那一筆**：以前會選到同一行的第一個符合處，而且從尋找視窗點時用的是別的搜尋的關鍵字。
- **單一檔案超過 500 筆時會告訴你**：以前多的會默默不見，現在結果標「+」並提示哪些檔只列前 500 筆。
- **搜尋還在跑時再按搜尋**：舊的會取消、結果丟掉，不會再出現「舊的結果蓋掉新的」；列檔案階段也能取消；取消時不會再說「沒有找到」。
- **只有 CR 的換行也算一行**，行號不再偏。
- **任何 BCB6 原始碼樹（HT9011UC_Code_*）都不會被取代**，不只 golden 那一棵。
- 搜尋歷史刪除時沒有指定哪一筆就不動作（以前會刪掉第一筆）；歷史記錄的選項改存複本。方案總管篩選上限給 0 時不再變成 2000。
## 0.221.0
- **安全：停止（⏹）、重新啟動、▶ 和 F5 前，會先讓程式「正常關站」**（agent 檢查執行列找到的）。以前會直接強制結束 wb_serve（taskkill /F），程式自己的關站（馬達和 1203 軸停止、加熱繼電器關掉、資料存檔）都沒做。現在先送程式自己的關站訊號（跟主畫面 Exit、`stop_wb_serve.ps1` 一樣），等它結束（最多 30 秒）；沒結束才強制，而且會跳警告提醒確認機台狀態。程式被除錯器暫停時沒辦法回應，才直接停。
- **安全：F5 時，關掉舊程式改到最後才做**：以前在問「要不要不接除錯器啟動」之前就先把舊程式砍掉，按「取消」舊程式也已經沒了。
- **安全：「▶＝F5」模式下，方案總管工具列的「模擬」「Debug」勾選變灰**，滑鼠停上去會說明原因（▶ 用的是「執行與偵錯」選的設定，勾選不影響），避免勾了模擬以為在跑模擬、其實跑出貨組態。
- **重新啟動（↺）**：重新啟動原本在跑的那個設定，不是目前下拉選到的。
- **停止只停這個資料夾的偵錯**，不會把別的資料夾的一起停掉。
- **建置完整性**：「已經編過就跳過建置」以前會把**被砍斷的 exe**（尾巴少一截、或檔頭全是 0）當成好的直接啟動 → 現在會檢查 PE 結構，不完整就重新連結。取消建置後寫到一半的 exe 會重試刪除，訊息照實說。連點兩下 ▶ 不會再跑兩次建置。
- 除錯暫停時焦點在「執行緒」也算暫停（以前繼續／逐步按不了）。
## 0.220.0
- **效能**：設計畫面開著「顯示所有元件名稱」「接線狀態」「DFM 位置」「Tab 順序」時，以前每畫一次都讓瀏覽器對每個元件重新排版一次（大頁面一次 0.2～0.6 秒）；現在先量完全部位置再一次畫上去。
## 0.219.0
- **與另一頁比較…**（設計畫面右鍵「檢查與比對」）：選另一頁（名稱相近的排前面，例如 HT9045 版和 HT9050 版的同一頁），用元件名稱逐一比對，開一份報告：**只有這頁有**、**只有那頁有**、**兩邊都有但不一樣**（型別、文字、位置、大小、顯示／隱藏）。
- **跨頁面取代文字…**（同一個子選單）：輸入要找的字和要改成的字，選「整個文字一樣的才改」或「文字裡有這段的都改」，列出**所有頁面**上符合的元件（全部預設勾選，可以取消勾選），按 Enter 一次改完；**一次 Ctrl+Z 全部復原**。只改元件上顯示的字（按鈕、標籤、標題、輸入框的值），不會動到程式、樣式、名稱。改完還沒存檔（全部儲存 Ctrl+K S）。
## 0.218.0
- **效能（agent 量到的熱點）**：
  - **複製／Ctrl+D 一個很大的容器以前要卡 25 秒**（例如 IO 頁最大的面板）→ 現在 0.01 秒。
  - **很寬的 CSV（例如 1002 欄的 Task_ListWithTime）捲動以前每一步 0.3 秒** → 現在 2 毫秒（只畫看得到的欄）。
  - 大頁面上找上層元素／上移下移／分頁操作快 4～5 倍。
  - 設計畫面閒置時不再每 0.4 秒重畫全部標示（開了名稱／接線／DFM 位置時以前會把 CPU 吃滿）；頁面外圍的時鐘、狀態列變動不再觸發元件樹重建；找不到的元件名稱不再每次掃全部分頁；拖到邊緣自動捲動時不再每 30 毫秒重算對齊線。
- **上移一層／下移一層**：以前會把中間的文字（例如「<select> Baud」）搬到另一邊、把元件前面的註解留在原地 → 現在兩個元件原地交換、中間的東西不動、註解跟著元件走；上移再下移完全回到原樣（全部頁面 12274 次實測 0 差異）。
- 有一個沒關的 `<div>` 的頁面（MotionView）以前「找不到上層元素」，現在照瀏覽器的方式處理。
- 手寫頁面（主畫面、LotInfo、TesterComm…）的分頁：選到藏起來的分頁裡的元件，會自動切到那個分頁。
## 0.217.0
- **CSV 填滿數列**：小數會照步長和位數（0.5、1.0 → 1.5、2.0；1.9 → 2.9、3.9，以前變成 0.6、1.10）；「M-01」的「-」不再被當成負號（→ M-02、M-03）。
- CSV：切換「第一列是標題」後重複值會重算；「清除所有篩選」放回篩選那一組；「下一個可疑的格子」會跳過被篩選藏起來的；編輯格子時按 Ctrl+Y 不會再把打的字丟掉。
- 設計畫面：切到操作模式時，設計中的狀態（Tab 順序設定、拖曳中、量距離、放大鏡）一起結束（以前 Tab 順序設定會留在操作模式，Esc 也傳不到頁面）；F2 的文字框會跟著頁面捲動；捲動停止的位置會正確記住（以前重開會回到錯的位置）；頁面 JS 錯誤數超過 20 也照實顯示。
## 0.216.0
- **修正：尋找視窗的「取代／全部取代」可能改到別的搜尋結果**：以前在尋找視窗搜 A、視窗關掉後又從方案總管「在這裡搜尋」搜 B，再打開尋找視窗按「全部取代」，會用 A 的文字去改 **B 的結果**。現在尋找視窗只用它自己的搜尋結果；「全部取代」也只取代列出來的（前 2000 筆）。
- **修正：多選時「重設（改回 DFM）」對底線、刪除線、WordWrap、ReadOnly、Checked、MaxLength、TabOrder 沒作用**（以前說「跟 DFM 一樣」）→ 現在每個元件改回它自己的 DFM 值，一次 Ctrl+Z 復原。
- **修正：智慧標籤 ▸「編輯項目」沒有跳到屬性面板的 Items 框** → 現在會跳過去。
- 寫回原始碼前再檢查一次：樣式值不能有 `; { } < > \`、不能寫 on… 事件屬性（防護）。
## 0.215.0
- **修正：寫回 HTML 原始碼時可能寫錯地方或亂改位元組**（agent 枚舉全部 82 頁、5 萬多個元素找到的）：
  - 改屬性（Caption 文字、Enabled、Checked、ReadOnly…）以前會把屬性**搬到標籤最後**、吃掉前面的換行、把 `&` 改寫成 `&amp;`；而且在 title／placeholder 裡出現 `value`、`disabled` 字樣時可能改到別的屬性裡。現在只改值本身、原地改，值一樣就完全不動。
  - 有些元件的 id 只出現在頁面的 JavaScript 字串裡（例如教點頁），以前會被當成真的元件，修改可能**寫進 JavaScript**；`data-id` 也被當成 id。現在只認真正的標籤。
  - 改下拉選單／單選群組的項目，以前會把每個 `<option value="…">` 的 value、項目間的註解、`&#x27;` 這類字元弄掉 → 現在只改有變的項目，其他原封不動；項目一樣就完全不改。
  - SVG、清單（ListBox）、沒有標題列的 Panel、圖片／圖表佔位等，以前按 F2 或改 Caption 會把字塞進元件裡 → 現在這些沒有 Caption。
  - 輸入框、圖片以前「跳到原始碼的 Caption」會跳到旁邊別的元件。
  - 分頁標題前後的空白不會再被吃掉；內容沒變的 Caption 不會再被重新編碼。
## 0.214.0
- **修正：屬性面板的修改可能套到「剛換選的」元件上**（agent 枚舉找到）。例如在元件 A 的 Left 按 ↑ 之後馬上點元件 B，A 的新數值會寫到 B；在 A 開的右鍵選單（重設／改回 DFM）或字型對話框，換選 B 之後按下去也會作用到 B。現在：
  - 換選之前，面板先把 A 還沒寫出去的修改結束掉、右鍵選單和字型對話框關掉；
  - 每個修改都帶著「它是給哪個元件的」，對不上就不套用（狀態列說明）；
  - 頁面剛重畫時，修改用元件名稱找元件，找不到就不寫（以前可能寫到別的元件）。
## 0.213.0
- **CSV 表格修正（agent 枚舉 100 個真實 CSV 檔＋每個快捷鍵找到的）**：
  - **很快連續修改兩格時，第二格可能寫到錯的位置**（例如 Mot_Table 的軸資料被弄亂）→ 現在修改一個一個排隊寫，每次都以當下的檔案內容為準。
  - **檔案在別處被改過（另一個編輯器、Ctrl+Z）後，表格還沒更新就修改，會寫到隔壁列** → 現在這種修改會被擋下，表格自動更新，狀態列提示再做一次。
  - **分隔符號可能被改掉**：以前每次修改都重新猜分隔符號，在第一列打「;」、或刪掉／排序第一列，可能讓整個檔案被當成別的分隔符號、之後寫錯 → 現在開檔時決定一次，而且會跳過引號裡的字。
  - **錯誤的列號不再變成「第 1 列」**（以前可能誤刪標題列）；超大量貼上不會再當掉。
  - 勾「第一列是標題」時，Ctrl+A 後按 Delete／Ctrl+Enter、或篩選中刪除列，**不會再動到標題列**（只選標題列時照樣可以改）。
  - 只有一列資料的檔案，選一格按 Ctrl+－ 不會再把整欄刪掉（要先點欄字母選整欄）。
  - 排序：按「排序」確認之後才用當下內容計算（以前用確認前的）。
  - 引號：以前一格只要曾經需要引號（例如打過「a,b」），之後改回一般值還是會加引號 → 現在照檔案原本的寫法（檔案本來每格都加引號才加）。
  - 讀檔加快（大檔解析快數倍）。
## 0.212.0
