## 0. Summary

- **What the box is:** golden `CheckEmployeeID(AnsiString S1)` (mymessbox.cpp:1353-1369, "SECS GEM Confirm the Employee ID", Ifor 20180227 (Steven), KYEC). It opens `fPassword` with two captions, waits modally for an ID and a password, puts both into SVs 37008 and 37012, and raises CEID 70 "Barcode Reader Enter". **The handler compares nothing.** The host (EAP) decides and answers with S2F41 RCMD `AUTHORITY_CHECK` (Action 0 = pass, 1 or 2 = ask again with a host Message). The web contract already names this kind: `web/JSON/Dialog-bridge-contract.json:92` `"employee-id": "CheckEmployeeID / SECS GEM S10F3"`.
- **Port today:** `CheckEmployeeID` is not defined anywhere. Its only port call site, `WebStart.cpp:1452-1459`, sits inside `#if 0` (SAFETY-GATE W906-ST-W1-G). The gate's reason: the port's `fPassword->ShowModal()` is a no-op, so a straight translation would report **blank** credentials to the host. Nothing at runtime can reach the box anyway:
  - the two writers of `bEnableEmployeeIDCheck=true` are not ported;
  - the Timer1 state machine is not ported;
  - **the SECS host link itself is not live in V906**: `THGem::Timer1Timer` has no caller, `EventReport` only bumps a sim counter (SECSGEM/SecsEventReport.cpp:15-19), and TFSECS is not translated;
  - `fPassword` is NULL at runtime because nothing calls `InitForms()`.
- **D-026 reuse:** reuse the `dialog.auth` command name, its token exemption, the `HT9045Recipe.dialogAuth` client method, `Alert.Password.html` / `login-page.js` (which already switch Label5/Label6 for `kind==='employee-id'`), and the WebLogin wipe/convert helpers. **Do not reuse** `W906_NoteAuthVerify` or `W906_Reauth`. They compare a password locally against the note's level or the book, they are bound to an alarm qid or to `editlist.save`, and the auth layer only opens when the operator presses a closing action on an Alarm/Message box. This box is opened by C++. It needs a small St02 adapter (new files), a blocking wait in wb_serve (an EOF append that needs the laptop's OK), and a little web glue.

### 1.4 Pass, fail, cancel, timeout

| Case | What golden does |
|---|---|
| Pass | Host `Action`=0. The HCACK=0 handler sets `iShowAUTHORITY=2` (only while MyMessageBox or fNote is shown). Next Timer1 tick: 2 becomes 3. For a SECS alarm, it closes MyMessageBox and hides `palWaitEAP`. Once MyMessageBox is not shown: `iShowAUTHORITY=0; iTimeOutCount=0; bEnableEmployeeIDCheck=false; bWaitSecsGemReply=false; bSECSGEMAlarm=false`. A KYEC note still asks for the D-026 login (note.cpp:1922-1925). |
| Fail / ask again | Host `Action`=1 or 2 sets `iShowAUTHORITY=1; strShowAUTHORITY=Message`. Timer1 calls `CheckEmployeeID(Message)`, so the box comes back with the host's text in Label6. |
| Timeout | No reply within `iN07_EmployeeIdCheakTime` seconds: `iTimeOutCount++` and the timer restarts. After 3: close MyMessageBox, hide `palWaitEAP`, `iShowAUTHORITY=3`, clear the flags. The machine then goes back to the normal flow (「Time Out 3次後不等待EAP回覆，跑原本流程」). |
| Cancel | Blank ID and password are put in the SVs, CEID 70 is raised, `bWaitSecsGemReply=true` (spbCancelClick :125-127 runs, then the :1361-1364 tail). |
| Replies to host | S2F42 HCACK. 0 = accepted, or [N07-5] off. 1 = not a LIST, a bad item or an unknown name. There is no "rejected" code: the verdict belongs to the host. |
| Logs | None. No RecordProcess / MyDBIProcess in CheckEmployeeID or in the AUTHORITY_CHECK branch. The only trace is the SECS event. |

### 4(d) Human-review items (register through ST01-M)

1. **KYEC-only flow** (CC_KYEC_LEE; [N07-5] is visible only for KYEC_LEE / JSCC_OS / SCC).
