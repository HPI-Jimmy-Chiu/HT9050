# 更新紀錄

每一版多了什麼。怎麼操作看 [操作一覽](CHEATSHEET.md)，詳細說明看 README。

## 0.312.0
- 第九批程式審查（最早的 0.1–0.59，基礎索引與跳轉）——到這裡整個外掛的歷史都審過一遍：
  - **檔案監看**：同一個資料夾、同一種檔案的所有監看都會被通知。以前只有第一個註冊的有效，存了頁面後 CodeLens 和「在設計檢視顯示」一直是舊的。
  - **命令追蹤**：
    - `!=` 不再當成命令分派。
    - 權限白名單（`if (c=="x") return true;`）排在真正的分派後面。以前 pause.run、auth.login、motor.stop 會跳到 MainClose.cpp 的關站白名單。
    - 找處理函式時不再越過 `} else` 吃到別的分支。以前 act.home.abort 會多列兩個不相干的函式。
  - **索引**：
    - 路徑大小寫不同（D:\ 和 d:\）也認得是同一個檔，不會出現兩份。
    - 同一個檔同時存兩次不會重複加入。
    - 分析快取有上限（以前全樹約多佔 110 MB）。
  - **重新跑 dfm2rc 後**：表單清單和 CodeLens 會自動更新，不必重新載入視窗。
  - **CodeLens 與「游標在哪個函式」**：`#if 0` 裡的舊副本和字串裡的名稱不再被當成函式定義。以前移植樹有 21 處死副本、19 處字串被掛上「設計檢視」。
  - **golden 樹**：
    - `/* */` 註解裡的舊定義不再當成現行定義（例如 TTrayMotor::HasIC 現在跳到真正的第 1061 行，不是註解掉的第 1053 行）。
    - 唯一一個 UTF-8 的檔（cSiteUseManager.cpp）不再顯示成亂碼。
    - 內容更新後索引會自動重建。
  - **超過 60,000 字的函式**（TfMain::FormShow、TfMain::Start 等）：游標在後半段也找得到。
  - **雙擊事件跳程式碼**：等候期間換了選取，不會跳到別的元件的函式。
## 0.311.0
- 第八批程式審查（0.60–0.99，基礎部分）：
  - **自動接線找送命令的程式**：只認真正「定義」rawCmd 的程式。以前會挑到 ht9045_dialog_host.js（它只該由 background.html 載入），有 20 頁會被插入它，畫面說接好了，事件卻到不了 C++。目前沒有任何頁面已經被插入。
  - **新增事件**：分派表裡其他表單的某一列產生不出來時，這次就不接並說明原因。以前會把那一列悄悄丟掉，那些按鈕就不再呼叫 C++。
  - **改名、群組、解除群組**：計算期間頁面如果又被改了（剛拖過或正在打字），就不寫入並請你再做一次。以前會用過期的位置把 HTML 標籤切壞。
  - **跳到 DFM**：會核對那一行真的是 `object 名稱`，不是就在檔案裡找。實測 912 版 golden 上，修正前 6,746 個元件（30%）指錯行，修正後 0 個；這個版本 .dfm 裡沒有的元件會直接說明。
  - **程式碼 → 設計檢視**：游標在事件處理函式最後幾行時，不再跳到下一個函式的元件。
  - **名稱檢查**：事件函式名稱和元件名稱不能用 C++ 保留字（delete、new、class…）、__ 開頭，或表單本身已有的成員名稱（Close、Show…）。以前會讓 9050 編不過。
  - **寫檔**：目標檔被暫時鎖住時會重試，不會在移植樹留下 .htd-*.tmp 殘檔。
## 0.310.0
- 第七批程式審查（0.100–0.129）：
  - **多選時值不同的欄位**（顯示「（不同）」）：
    - 點進 Caption 按 Enter，不會再把所有元件的文字清空。
    - 在 Left、Width 這類數字欄按 ↑↓ 或拖名稱，不會再把所有元件設成 1。
    - 要改就直接打值，打了才會套用到全部。
  - **同時選了容器和它裡面的元件**：拖曳、方向鍵、Ctrl+拖曳複製只動最外層，子元件不會被移兩次（跟 WinForms 一樣）。
  - **鎖住 TabSheet**：分頁裡的元件也一起鎖住。
  - **CSV 表格**：Ctrl+X 之後插入或刪除列、或按 Ctrl+Z，這次剪下會取消。以前貼上時會清掉別列的格子。
  - **事件處理函式改名後按 Ctrl+Z**：存 .h 時分派表會改回舊名字，按鈕不會失效。改名沒寫進去時，分派表也會改回去。重新產生時有任何一列產生不出來，分派表就不改。
  - **多選重設**：Font.Underline、StrikeOut、WordWrap、ReadOnly、Checked、MaxLength、TabOrder 這幾項多選時不能一起改回 DFM，選單會說明。以前會說「跟 DFM 一樣」，實際上什麼都沒改。
  - **對齊格線**：尺寸不是 px 的元件會說清楚原因，不再說「已經在格線上」。
  - **拖曳中按 Esc 取消**：放開滑鼠後選取不變。
## 0.309.0
- 第六批程式審查（0.130–0.159）：
  - **改名稱也改頁面樣式**：頁面 `<style>` 裡的 `#舊名{…}` 會列進改名清單（預設勾選）。以前沒改，元件外觀直接跑掉；30 頁共有 177 處這種寫法。
  - **RadioGroup**：
    - 改名時，它自己的按鈕群組名（name="rg_舊名"）跟著改。以前之後新增的 RadioGroup 會跟它變成同一組。
    - 增減項目時，列數照產生器的規則跟著改（列數＝項目數÷欄數，無條件進位）。
  - **TRadioButton 勾 Checked**：同一個容器裡其他 RadioButton 的勾會一起取消（跟 VCL 一樣），一次 Ctrl+Z 全部復原。
  - **設定 Tab 順序**：只編號能停住游標的控制項；勾選框寫到裡面的 `<input>`。Label、Panel、GroupBox 不再被加上 Tab 停點。
  - **多選**：
    - Items 列不顯示（它只改得到一個元件），Picture 的「選擇…」也不顯示。
    - 接點擊事件時，選取的元件裡如果有頁面程式自己送 WS 命令的，就不能一起接（以前點一下會派送兩次）。
    - 「只保留連線」的情況，網頁上那行註解照樣寫入（跟單選一樣）。
  - **改名時判斷「共用程式」**：會算整個 web 樹的頁面，包括 web\background.html。
## 0.308.0
- 第五批程式審查（0.160–0.189，設計器）：
  - **事件分派表**：
    - 重新產生時，有任何一列產生不出來（例如那張表單的 .h 正在編輯），整張表就不改，並列出是哪幾列。以前會把那幾列悄悄丟掉，那張表單的按鈕就不再呼叫 C++。
    - 刪除事件後按 Ctrl+Z 找回來，網頁存檔時分派表那一列會自動補回。以前只回復一半，按鈕悄悄沒反應。
  - **刪除事件連函式一起刪**：先查整棵移植樹有沒有別的檔在用這個函式（fHotPlate->函式、TfHotPlate::函式），有就保留函式。
  - **群組到 GroupBox**：在沒有產生器 .gbx 樣式的頁面（283 頁裡有 239 頁），元件不再偏移 (+2, +10) px，用 Edge 實測過。
  - **拿著工具時按住 Ctrl**：就是暫時切成選取工具，可以選取、移動，不再變成複製或多選。
  - **連續放置**：放完第一個、頁面重新整理後，工具還拿在手上。
  - **比例縮放**：AutoSize 標籤（寬度 auto）會縮位置、保留自動寬度，不再整個被跳過。
  - **在容器空白處拖框選取**：只選那個容器裡的元件（跟 WinForms 一樣）。
  - **解除群組**：網頁程式有用到那個容器、或容器本身是隱藏的，會先問你。
  - **字型對話框**：
    - 多選時，你動過的欄位一律套用到所有選取的元件。
    - 大小旁邊會顯示換算成 BCB 的點數（pt）。
  - **復原歷史**：同一個元件 2 秒內的連續打字算一步；快照總量有上限，不會無限佔記憶體。

## 0.306.0
- 第三批程式審查（0.222–0.249）處理完：
  - **異常字元檢查不再碰其他 Big5 專案**。以前開 GPIB／ESD／HT9046LS 這類 BCB6 原始碼，一個檔會被標上千個錯誤，還叫你「用 UTF-8 重新輸入」，照做原始碼就毀了。現在：不在 C++ 移植樹、而且內容主要不是 UTF-8 的檔不檢查；UTF-8 檔裡混進少數 Big5 位元組照樣會標出來。
  - **Make（Ctrl+F9）建置中按 F5 會請你等**，不會兩個建置同時寫同一個資料夾。
  - **Make 只關要建的那支程式**（它的 exe 被鎖住就連結不了），不再一次關掉這棵樹所有的 wb_serve。F5 照舊。
  - **資料夾改名**：include 目錄（例如 ${CMAKE_CURRENT_SOURCE_DIR}/Common/PickPlanner）會跟著改。# 註解不算、不改。根目錄的 Public 資料夾不會碰到 CMake 的 PUBLIC 關鍵字。
  - **刪除資料夾**：確認框會說裡面共幾個檔，以及清單上看不到的其他類型檔案。
  - **匯出 PNG**：先畫到暫存檔，成功才覆蓋你選的檔；失敗時舊圖還在。
  - **F5 的等待頁打不開**（沒有瀏覽器、沒有 boot_wait.html）只當警告，建置成功照樣啟動。
  - **搜尋**：背景執行緒中途出錯不再改在主執行緒重跑（以前結果會重複，遇到卡住的正規式還會凍住 VS Code），直接告訴你原因。
  - **新增事件處理函式**：表單類別的 private 區裡有帶 public: 的巢狀 struct 時，新函式不再被放進 private 區。
  - **新增 C++ 檔加入 CMake**：插入位置改用當下內容重算。
  - **存檔時的編譯器檢查**：超過 2 分鐘會整個結束，cc1plus 不會留下來繼續吃資源。
- **停止鈕**：兩次「偵測程式是否在跑」重疊時，舊結果不再蓋掉新結果（以前程式還在跑，停止鈕卻可能變灰）。
## 0.305.0
- 第二批程式審查（0.250–0.277）的 11 項全部處理完：
  - **機台開關（MachineType.h）**：以前什麼都不改直接按 OK，會把 DEBUG_HANGUP_NO_HOME／DEBUG_ATC 打開。原因是 #ifdef SOFT_SIMULTE 裡的同名 define 也被列成開關，勾選又用名稱比對。現在只列最外層的開關，勾選改用行號比對。

    - 建置期間會上鎖，不會跟清除／全部重建同時建同一個資料夾。
    - 有別的建置工作在跑時會等。
    - 不建 build\（oracle 線的基準）。
    - 清除／全部重建也加上「別的建置在跑就等」。
  - **CMake 加入／移出建置**：
    - # 註解裡的檔名不再算進去，也不會被刪。
    - 移出某個檔時，如果 set_source_files_properties(...) 只剩它一個檔，整段呼叫一起拿掉（不然下次設定會報錯）。
  - **元件改名「一起改 C++」**：其他檔裡的 fMain->元件名 也一起改。選單上會顯示「其他 N 個檔 M 處」；註解、字串和較長的名稱不動。

  - **Find Error**：「ntdll.dll+0x1234」這種別的模組的位址會說清楚查不到，不再算成這支程式裡的錯函式。
  - **機台資料夾切換**：同一支程式 15 秒內換成另一台機台再啟動，也會切換資料夾。
  - **停在中斷點時 F5＝下／拿掉中斷點**（跟 BCB 一樣）。沒在除錯時 F5 仍是建置並啟動。
  - **書籤**：沒有書籤移動時，不再每打一個字就存檔並重畫。
  - **StringGrid／清單編輯**：最後多一個換行，不再多出一列空列（跟 BCB 的 TStrings 一樣）。
  - **建置進度**：連按兩次 F5 時，第二次的 Ninja 進度不會因為 Windows 沿用舊的建立時間而不顯示。
