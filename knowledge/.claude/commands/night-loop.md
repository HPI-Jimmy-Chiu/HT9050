## 步驟 -1 — ★ 奪權（**第一個動作，在讀時鐘之前**）

夜間鏈是**兩段式、絕不並行**（使用者 20260915 17:00 裁決）：

```
17:00 ──────────────────────────► 04:00 ──────────► 07:30
        工作段                              收尾段
   /st-wave ──(kWave7State=2/3)──► /fw-wave      /night-loop
```

本指令的 cron 是 `7,27,47 4-7 * * *`，所以**第一次觸發就是接班時刻**。
接班的第一件事是把工作段關掉：

1. `CronList`。
2. 凡是 prompt 為 `/st-wave` 或 `/fw-wave` 的 job，**一律 `CronDelete`**。
   用 prompt 內容找，不要寫死 id。
3. 記下你刪了哪些，寫進晨間報告 §5。

### ⚠ 為什麼一定要先奪權（這是硬理由，不是整潔癖）

本指令的 **B 線（收攏未 commit 的日間工作）** 與 **C 線（處理刻意標記未處理的項目）**
會**碰跟戰役同一批檔**。如果 `/fw-wave` 還活著，它的**在製工作**會被 B 線看成
「該 commit 的日間工作」而收走 —— 那是把別人做到一半的東西提交出去。
D 線的衛生哨兵還可能跑整套 gate，跟戰役的 build 撞同一個 build dir。

⚠ **奪權要做，「不介入」也要做**：刪 cron 是擋**新的**波次開始；
如果步驟 1 看到**已經在跑**的 build / ctest / agent，照樣不介入，讓它跑完。
兩件事不衝突，順序是先刪 cron 再看有沒有在跑的。

## 步驟 0 — 讀時鐘，決定模式

```
date +%H:%M
```

- `< 07:00` → **工作模式**，往下做。
- `07:00 ~ 07:30` → **收尾模式**：跳過步驟 2，直接做步驟 3。
- `> 07:30` → **靜默模式**：只確認 `docs/NIGHT_REPORT.md` 今天已經寫好、
  `git status` 是乾淨的。**一個檔都不要動**，回報一行就結束回合，
  並呼叫 `ScheduleWakeup({stop: true})`。

不要憑「上一輪是什麼模式」推論 —— 迭代之間可能隔了很久。

## 步驟 2 — 四條線，照這個順序

`$ARGUMENTS` 指名某一條（`A` / `B` / `C` / `D`）就只做那一條。空的話全做。

**D 先做**（最便宜、會擋住其他線）→ **A** → **B** → **C**。

- **D 衛生哨兵**：接線回歸、配方母體漂移、`system/` 指紋、absence-claim 重驗。
  **紅燈就停下來查**，不要記一筆繼續跑。
- **A 髒資料**：可再生的直接刪；不確定的搬到
  `D:\HT9045\backup\night_quarantine\YYYYMMDD\` 並寫 `MANIFEST.tsv`。
  ⛔ `system/` `config/` `CFG/` `IniData/` `setup.inf` 一律不碰。
- **B 未 commit 的日間工作**：每個檔要過三關（能歸屬 / 已停止變動 / gate 綠）
  才可以 commit。**看不懂的不要猜，留著並寫進報告。**
  push 要四個條件全中（gate 綠 / 三關都過 / 分支對 / 不繞過 hook）。
- **C 刻意標記未處理的**：安全關鍵一律**佇列、不做也不問**；
  非安全且信心 ≥90% 才做，單獨一顆 commit + 完整 gate。

判定一律用 `tools/gateverdict.sh <tag>`，**絕不看 ctest 的 exit code**（它對任何
失敗數都回 8）。

## 步驟 3 — 收尾（07:00 之後每一輪都要確認做完）

1. 手上的收到可提交、樹是綠的狀態；收不完就 `git stash` 並寫明。
2. `git status` 乾淨，或逐檔列出剩下的別人的在製工作。
3. 隔離區 `MANIFEST.tsv` 寫完。
4. 比對 `system/` 指紋 —— 有變動但今晚沒跑 build，那是**真發現**，寫進 §3。
5. 整份重寫 `docs/NIGHT_REPORT.md`（§0 分流表 / §1 做完 / §2 佇列 / §3 紅燈 /
   §4 清理 / §5 commit-push）。§0 空就寫「今晚沒有需要你介入的事」，
   **不要拿 §1 的內容塞進 §0 充數**。
6. 更新 `docs/DEVLOG.md` 的 🔖 RESUME（下一步具體到檔名行號）。
7. `ScheduleWakeup({stop: true})` + `CronDelete` 掉 `/night-loop` 自己那個 job
   （步驟 -1 已經刪掉 `/st-wave` 與 `/fw-wave`）。收工後不該有任何 cron 還活著。

## 步驟 4 — 續命（只在工作模式做）

回合結束前不准是閒著的：沒有背景工作在跑就開下一項。
`ScheduleWakeup` 當保險（1200–1800 秒），cron 心跳當時間表 —— **兩個都要**，
因為它們的失效方式不同（鏈斷 vs 漏一次）。
