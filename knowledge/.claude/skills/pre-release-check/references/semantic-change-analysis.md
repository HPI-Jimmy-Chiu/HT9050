# Track C — 語意變動分析

> 在步驟 6 時，與 Track A（編譯）和 Track B（MD 草稿）平行啟動。

---

## 目的

風險掃描（Batch A/B/C）著重於「**既有程式碼的靜態缺陷模式**」，但無法判斷**本次修改是否改變了原本的執行語意**（例如：條件式改寫後行為等價嗎？迴圈邊界調整是否如預期？）。

Track C 專門負責這項判斷。

---

## sub-agent prompt 範本

```
你是 C/C++ 程式碼語意分析專家。

以下是本次被修改的程式碼片段（來自 Batch A/B/C 掃描命中的行號，以及其上下文 ±20 行）：
<貼入各 Batch 回傳的命中代碼片段>

請判斷每一處修改是否造成語意變動，分類如下：

1. **等價重構**（語意不變，例如：僅格式化、重新命名、移動順序）→ 標記 OK
2. **語意變動 — 明確**（邏輯或行為確實改變）→ 標記 CHANGED，說明改變內容
3. **語意變動 — 不確定**（無法確認是否等價，需要業務知識）→ 標記 UNCERTAIN，提出具體問題

輸出格式：
| File | Line | Change Type | Description | Question（若 UNCERTAIN） |

對於所有 CHANGED 與 UNCERTAIN 項目，列出需要向開發者確認的問題清單。
```

---

## 主 agent 後處理規則

| 分類 | 後處理 |
|------|--------|
| **OK** | 不列入 findings；在報告附錄記錄「語意等價已驗證」清單 |
| **CHANGED** | 列入報告，標記 Severity = High，提醒使用者人工複核 |
| **UNCERTAIN** | **主動向使用者提問**（依 Track C 輸出的 Question 欄位逐條詢問），等待回覆後再更新報告狀態 |

> ⚠️ Track C **不得自行決定** UNCERTAIN 項目是否安全，**必須向使用者確認後**才能標記為 OK 或 CHANGED。
