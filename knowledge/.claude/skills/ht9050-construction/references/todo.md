## 維護規則

- ID 格式為 `<分類>-<三位數>`，例如 `F-001`；同一 ID 不得同時存在於本檔與 `done.md`。
- 一件工作只選一個主分類；跨領域依賴寫入「依賴／阻塞」，不要複製成多列。
- 每列必填狀態、負責、風險、依賴／阻塞、完成證據與下一步；未知不得留白，寫 `UNKNOWN`。
- 實作型 ID 在程式落地且靜態／建置證據齊備後，可用 `IMPLEMENTED` 搬入 done；驗證型 ID 若仍缺 runtime、真檔或機邊證據，即使程式已在也留在本檔。有環境相符的實測才可標 `VERIFIED`。
- 做完後將整列搬到同分類的 `done.md`，補上日期、commit／檔案、環境與限制；不可只劃刪除線。
- 旁支、其他 worktree 或未合入 commit 只能當參考，合入目標 HEAD 前不得搬到 `done.md`。

狀態使用：`INTEGRATING`、`SPEC_ONLY`、`BLOCKED`、`NOT_STARTED`、`UNKNOWN`。`IMPLEMENTED` 只表示程式已在但完成證據尚未齊全。
