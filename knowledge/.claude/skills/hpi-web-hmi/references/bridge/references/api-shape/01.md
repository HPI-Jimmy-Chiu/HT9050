## 四、API 形狀

### 4.1 核心切分：型別表產生、實例綁定手寫、頁面投影沿用 pagewire

**（一）每個結構型別一份產生的欄位表**

```cpp
// gen/sjson_SYSTEM_TEST_IF.gen.cpp   ← 由結構宣告產生，788 筆（見 §十二）
static const FieldDesc kTestIF[] = {
//  欄位名            offset                                   型別    區段              鍵          預設
  { "dSiteXPitch",  offsetof(SYSTEM_TEST_IF, dSiteXPitch),  F_F64, "Configuration", "X Pitch",  "0.1" },
  { "iTestMode",    offsetof(SYSTEM_TEST_IF, iTestMode),    F_I32, "Configuration", "Test Mode","0"   },
  { "iSiteMap",     offsetof(SYSTEM_TEST_IF, iSiteMap),     F_I32, "Site Map",      "Site%d",   "0", /*dims*/ {MAX_SITE_ROW, MAX_SITE_COL} },
  ...
};
```

- 來源：`ReadIniData(szDir, "Configuration", "X Pitch", 0.1)` 這一行就含 `[欄位, 區段, 鍵, 預設值]`；`strncpy(S.Alias, …)` 是字串欄位的等價寫法。
- **`offsetof` 一律由 C++ 產生**（產生器輸出的是 C++ 原始碼，編譯期算 offset），Python 不推算任何位移。二進位結構（`LAST_GENERAL_SET`）尤其如此。
- 二進位結構沒有 `ReadIniData` 可抽，欄位表改由**解析標頭的結構宣告**產生，區段／鍵欄留空。

**（二）每個實例一筆手寫的綁定**

```cpp
static const Binding kBindings[] = {
//  名稱                實例                型別表        持久化                              存檔鉗制（golden ③ 搬過來的）
  { "testIF.file",     &TestIF_File,     kTestIF,     Ini(RecipeDir, "Tester.Data"),      ClampTestIF    },
  { "testIF.live",     &TestIF,          kTestIF,     NoPersist,                          nullptr        }, // 唯讀
  { "deviceForm.file", &DeviceForm_File, kDeviceForm, Ini(RecipeDir, "Contact.Data"),     ClampDeviceForm},
  { "hotPlate.file",   &HotPlateForm_File,kHotPlate,  Ini(RecipeDir, "HotPlate.Data"),    ClampHotPlate  }, // cHotPlate.cpp:495-510
  { "levelSet",        &LevelSet,        kLevelSet,   Blob(SystemDir, "levelset.dat"),    ClampLevelSet  }, // cSecurity.cpp:1483-1508
  // _NET 一律不列（裁決）
};
```

**寫檔路徑綁在這裡，不綁在序列化函式上。** 一個型別表服務多個實例；換配方只換 `RecipeDir`。
`Clamp*` 是手寫的，一個表單一個，內容是 golden `SaveSetupFile`／`GetLevelSet` 裡對值的鉗制**改寫成對結構欄位操作**；每個 `Clamp*` 檔頭要註明搬自 golden 哪幾行。

**（三）不針對頁面生成 function，用投影參數**

頁面要哪些欄位，`tools/pagewire/` 的 `[文件, 區段, 鍵]` 三元組已經記著，和 `FieldDesc` 的後三欄是同一組鍵。

### 4.2 端點

```
GET  /api/struct/                          綁定清單 ＋ 每個綁定的欄位數、持久化種類、可寫否
GET  /api/struct/<binding>/schema          欄位表（名稱／型別／維度／區段／鍵／預設／min／max）—— 只抓一次
GET  /api/struct/<binding>                 全部欄位，value-only
GET  /api/struct/<binding>?page=<Page>     只回該頁 pagewire 三元組對應的欄位
GET  /api/struct/<binding>?since=<ver>     只回自 ver 之後變動的欄位（無變動回 304）
WS   struct.put  {binding, values:{...}, dryRun:bool}   → ApplyResult
```

`ApplyResult`：`{ok, version, accepted:[…], rejected:{欄位: 原因}, changed:n, bytesDiff:n}`。**拒寫是 all-or-nothing**：任何一欄不合法就整筆不寫，不做部分套用後靜默成功（沿用 `system.levels.put` 的契約，`wb_serve.cpp:1475-1519`）。

規則：
1. **一個 golden 處理器一條 `act.*`**，名字照 `<單元>.<按鈕名去掉 btn/sb/spb 前綴與 Click 後綴>`：`btnClearCountClick`→`act.sortCT.clearCount`、`spbExeClick`→`act.counterClear.exe`。既有 `counter.clear` 保留為 `act.counterClear.exe` 的別名。
2. **守衛一律回報，不吞掉。** golden 的 `return;` 在網頁上會變成「按了沒反應」，那是最差的行為。每個 `return` 都對應一個 `guard` 字串。
3. `dryRun:true` 只跑守衛，不跑本體——頁面可以用它決定按鈕要不要 disable（取代 golden 靠 `Enabled=false` 做的事）。
4. 副作用（SECS／DB／OEE）**照 golden 叫**，但 `wb_serve` 沒帶起來的子系統（sqlite `MyDBIProductionData`、SECS）要 no-op shim 並在回應標 `sideEffectsSkipped:[...]`——`counter.clear` 的註解（`wb_serve.cpp:3300-3320`）已經是這個做法，沿用。
5. 動作與資料通道**共用 `Reload`**：動作改了 `LastSet`，回頁面的仍是重讀後的值。

### 4.6 開機配置廣播與 `cfg.resync`（使用者 20260923：「`#define SOFT_SIMULTE`／`HW.HandlerSys.html` 之類的定義也要有 JSON 傳輸，而且一開機就該傳；C++ 先開、HTML 後開時，要有 HTML→C++ 的訊號叫它重送機台配置檔」）

**機台配置** = 三層，全部在 HTML 畫任何東西之前就要到齊：

| 層 | 內容 | 來源 | 現況 |
|---|---|---|---|
| 編譯期定義 | `SOFT_SIMULTE`（`MachineType.h:63-64`，除非 `W906_NO_SOFT_SIMULTE`）、機型、硬體選配 `USE_*`／`IO_CARD_TYPE`… | `MachineType.h` **287 個 `#define`**，全樹 `#ifdef` 用了 **5,095 次** | **沒有任何 JSON**。現有 `machine.*` tag 只有 6 個（`customerCode`／`id.gpib`／`id.tester`／`id.type`／`state`／`stateSource`） |
| 硬體設定檔 | `Gerneral.ini`（`HSys.*`，`HW.HandlerSys.html` 那 214 個鍵） | `GET /api/system/gerneral` | 有，但要頁面自己去拉 |
| 功能開關 | `IniConfig`（`config.ini`） | `GET /api/system/config`（鏡像） | 有，同上；結構化版本在 P2b |

設計：

```

                          每個 #define 輸出一筆 {name, defined:bool, value?}；
                          #ifdef 判斷在 C++ 編譯期展開，所以拿到的是「這顆 exe 真的開了什麼」，
                          不是標頭裡寫了什麼）

          → snapshot 內含 tag 群 def.*（machine.defines 的投影）、hsys.*、cfg.ver
```

規則：
1. **編譯期定義只能由 C++ 出**，Python 不解析 `#ifdef`（有 `#ifndef W906_NO_SOFT_SIMULTE` 這種相依，只有編譯器算得對）。

4. 287 個 define 不全送：只送 `machine.defines/schema` 標了 `web:true` 的（`SOFT_SIMULTE`、機型、`USE_*` 硬體選配、`IO_CARD_TYPE`、`MAX_*` 容量常數），其餘留在 `/api/struct/machine.defines?all=1` 供除錯。
5. **這是所有頁面的前置條件**：`background.html` 在 `def.*` 到齊前不掛任何 `page/*.html`；`ht9045-html-json` 的「開站載入順序」那節要改成以這個 snapshot 為第一步。
