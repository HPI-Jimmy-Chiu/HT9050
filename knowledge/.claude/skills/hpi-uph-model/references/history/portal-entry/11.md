## 8. 離線 UPH 頁的兩種動作表模式（完整／精簡）

> **//Steven 20260922** 新增。以下規則只描述離線計算頁的模型，不是機台程式行為。

### 8.1 完整模式（16 個動作）

每批一個 cycle 的 16 個動作秒數，對應五條平行路徑（§2 的規則 1~3）。動作編號固定如下，
精簡模式的兩個時間就是由這些編號的區段加總而來：

| # | 動作 | 機構 | 屬於 |
|---|------|------|------|
| 1 | `IN_TP` | In Arm | Loader 下針（每批 × n_dip） |
| 2 | `IN_EXT` | In Arm | Rotate／Bottom 2D／Precisor |
| 3 | `IN_HPP` | In Arm | → Hot plate 放一組（**僅 Hot**） |
| 4 | `IN_HPK` | In Arm | Hot plate 取已 soak 一組（**僅 Hot**） |
| 5 | `IN_KIT` | In Arm | → Shuttle 站A 放 In-Kit |
| 6 | `SHT` | Shuttle | iLeft ⇄ iRight 單程 |
| 7 | `IDX_PICK` | Index | 站B 取 In-Kit |
| 8 | `IDX_TOSOCK` | Index | Y → Socket |
| 9 | `CONTACT` | Index/Socket | Z 下壓、Drop Contact |
| 10 | `SD` | Tester | Start Delay |
| 11 | `TEST` | Tester | SOT → EOT |
| 12 | `IDX_BACK` | Index | Z 抬起 → Y 回 Shuttle |
| 13 | `IDX_PLACE` | Index | 站B 放 Out-Kit |
| 14 | `OUT_OP` | Out Arm | 站C 取 Out-Kit |
| 15 | `OUT_EXT` | Out Arm | Rotate／4S／AOI |
| 16 | `OUT_OPL` | Out Arm | Auto 盤放料（每批 × n_dipOut） |

### 8.2 精簡模式（只有兩個時間）

| 名稱 | 定義 | 備註 |
|------|------|------|
| **Index cycle time** | `max( Σ1~7 , Σ13~16 )` | 入料側鏈與出料側鏈**分別**加總後取大者；Hot 與 Ambient 各一個值（Ambient 的 Σ1~7 不含 3、4） |
| **Index time** | `Σ8~12`（**含 TEST**） | 掃描測試時間時拆成「固定開銷 ＝ Index time − TEST 主值」＋ 該列 TEST |

每批週期與 UPH：

```
兩支 Index：P = max( Index cycle , Index time )      兩臂交替共用同一個 Socket
單支 Index：P = Index cycle + Index time             串行
UPH = 3600 / P × N_pick × Yield
```

精簡模式**不另計** Loader 下針次數、換盤攤提、事件排程器互鎖（視為已含在使用者輸入的
Index cycle time 內），但 **Soak 仍會被檢查**（見 8.3）。甘特動畫與整機動畫在精簡模式停用
（沒有逐動作秒數可畫）。

### 8.3 Soak 補正（Hot 模式必查）

`B_hp ＝ Hot plate 可用格數 ÷ N_pick`（無條件捨去，至少 1）＝ 一片加熱盤裝得下幾批。

> **跑完整片加熱盤的時間 ＝ Index cycle time × B_hp**。
> 若這個值 **小於 Soak time**，代表 FIFO 最舊那顆還沒 soak 夠就被取走，
> 週期必須被 soak 拉長 → **改以 `Index cycle time = Soak ÷ B_hp` 計算**。

```
if (hot && cycle × B_hp < soak)  cycle = soak / B_hp      // 自動補正，頁面會標出補正前後的值
```

這與完整模式的規則 1（§2）等價：完整模式是 `(Soak + T_in) / B_hp` 這條路徑參與取大，
精簡模式因為沒有 T_in 細項，直接用 `Soak / B_hp` 當下限。

### 8.4 Index cycle time 的基準顆數與縮放

Index cycle time 是**以一組 8 顆（2x4 mode）估的**：

| N_pick | 處理 |
|--------|------|
| > 8（例如 2x8＝16） | **× 2** |
| ＝ 8（2x4） | × 1（基準） |
| < 8（1x1／1x2／1x4／2x2…） | 理論上會縮短，但**沒有可靠公式，預設不縮**；請在多模式表的 `Index cycle` 欄**逐列手動輸入實機值** |

多模式比較表在精簡模式下，每一列（site mode × 溫度）的 Index cycle 欄都是可編輯輸入框，
改了就只影響那一列，另有「清除逐列覆寫」鈕。

### 8.5 Site mode 清單（依 `MachineType.h · eTestMode`）

可選（11 種）：`1x1` SingleSite、`1x2` DualSite、`2x1` DualSite2x1、`1x3` TriSite1X3、
`1x4` QualSite1X4、`2x2` QualSite2X2、`2x3` _6Site2X3、`2x4` _8Site2X4、`2x5` _10Site2X5、
`2x6` _12Site2X6、`2x8` _16Site2X8。常用預設＝`1x1／1x2／1x4／2x2／2x4／2x8`。

**NN mode（`QualSite2X2N`／`_6Site2X3N`／`_8Site2X4N`／`_16Site4X4`／`_32Site4X8N`）目前隱藏不給選**：
NN 的 socket 只用單排（`acarry.cpp` 裡 2X2N 與 1x2、2X4N 與 1x4 同一個 case），
所以每批要多次下壓，而且 **index time 與一般模式不同，實機值未定**。
補到實際 index time 後，把頁面 `SITE_MODES` 內的 `hidden:true` 拿掉即可。

**已停用**：`_8Site1X4`（1x4_8，海思）、`_32Site4X8M`（4x8 單臂）—— 現場已不使用，頁面不列。

⚠ `MachineType.h` 對 `_32Site4X8N` 的註解寫「雙Arm 32 Site」，但實際用法是 **NN mode**，
註解與現況不符，查程式時別被誤導。

### 8.6 溫度模式

| 模式 | In 側路徑 | 說明 |
|------|-----------|------|
| Hot | 動作 1~7 全走 | 經 Hot plate soak，受 8.3 的 soak 補正約束 |
| Ambient（常溫） | 跳過 3、4 | In Arm 從 Loader 吸完**直接放 Shuttle Kit**；無 soak、無 Hot plate 緩衝 |
| 比較 | 兩者同時算 | **頁面預設**；同一張表／圖列出 Hot（藍實線）與 Ambient（橘虛線）與 ΔUPH |

短測試時間時 In Arm 常是 Hot 的瓶頸，拿掉 Hot plate 兩步後常溫 UPH 明顯較高；
測試時間拉長到 Socket 主導後兩者收斂 —— 這是預期行為，不是計算錯誤。

實作對照：`IN_TP` 與 `OUT_OPL`、`IN_KIT` 與 `OUT_OP` 的預設秒數已**兩兩對齊**，
使常溫的 In Arm 一趟 ≡ Out Arm 一趟（使用者 20260922 提供的實機認知）。
