# HT9050 MotionView Runtime 與 layout

## 差異

正式 Main 與離線 Concept／UPH 各有入口；不能把概念演算法、layout 欄位或瀏覽器動畫當成 Runtime 資料。

## 入口與流程

HT9045 repo `Main.MotionView9050.html`：

- `liveSettings9050` 讀 `HT9045Recipe.list()` 及 `MV9050_DOCS=["tray","hotPlate"]`；這不等於已有 Production-update producer。
- `startPage` 先確認 `m.id==="HT9050"`，讀 layout、套表單與容量、建動畫；最後明確呼叫 `applyRuntimeState(null)`，顯示等待。
- `applyRuntimeState` 先 `stopSim`，只接受 `state.motionView` 的 `machine==="HT9050"`，`available===false` 則不投影。
- 合契約才 `applyLive`，以 `loader`／`hotPlate`／`inPP`／`outPP`／`inShuttle`／`outShuttle`／`index`／`dut` 的快照二值狀態擺到站點。
- `render` 在 `LIVE` 存在時返回；`boot` 的 SIM 播放／單步／重設亦以 `LIVE` 擋住。這是讀到的頁面條件，不代表目前 Runtime 真有發布資料。

LayoutEditor 的 `boot` 讀 `MotionView9050-layout.json`、`Machine-profile.json`；
`loadJson` 在 file 模式先試 `viaScript` shim，再試網路，HTTP 模式相反。
`flowSteps` 只依出料選項映射 layout 步驟，不是 UPH 排程器、Gerneral.ini 或機台工單。
`machine` query 是頁面標籤，不是已驗證的機種分派。

## 安全

本批未讀取即時配方、API 或機台設定，未更動 HTML／JSON／scripts。
要判斷 Runtime 是否可用，依 [hpi-motionview 目前接線](../../../hpi-motionview/references/runtime/current-main.md) 與當次來源；
等待／`runtimeSupported:false` 不當成真機故障。
