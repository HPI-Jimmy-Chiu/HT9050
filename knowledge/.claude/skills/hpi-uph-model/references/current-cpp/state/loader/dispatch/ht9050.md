# HT9050 的 Loader Task 與補盤返回值

來源 [V906 Loader](index.md)。完整所選文字已讀不代表 helper、教導值、感測器、馬達、所有上層派工或實機語意已驗證。

`DoLoad` 第一個機型分支 `MachineTypeChoice==Type_HT9050` 呼叫 `DoLoad_9050()` 並 return；發生在一般 `bOneTimeHotPlateCheckAll`／reset 檢查和 `switch(LoadTask)` 前。這是本地程式順序，不推定其他機構也忽略這些條件。

| 定位 | 本地證據 | 不能推定的結果 |
| --- | --- | --- |
| `DoLoad_9050`／`LoadTask_9050` | `iCatchFromLoader9050Task != 1` 先 return；`case 800` 在 `iCleanOut==1 || iOneCycle==1` 時 break，否則 init 補盤 Task 並轉 900；900 收到補盤 true 後回 Task 1 | 其他機構／取料流程及安全互鎖已完整核對 |
| `InitLoadNewICTrayTask_9050` | 只設 `iLoadNewICTrayTask_9050=1`，此短函式不重置 `iLoaderLayerCount_9050` | 任一 caller 也不會重置層數 |
| `DoLoadNewICTray_9050`／case 1 | `iLoaderLayerCount_9050==0` 直接 return true | 已供有效 IC／已產生 UPH 記錄 |
| 同函式／case 250 | 本地 Clean-out 分支，在 Selector Pop 與指定移動返回 1 後 Task=1、return true | true 一定代表正常供盤完成 |
| 同函式／case 300 | 設 `MMTrayY.fHasTray=true`、`SetTray(HAS_IC, __FUNC__)`，轉 Task 400 | 實盤每顆 IC／site 口徑或良率已確認 |
| 同函式／case 400 | 指定 Pop／移動條件後，可依 drawer sensor 與 SECS 開關送 `LoadTrayFinish`；其後 Task=1、return true | 發出 `UPHRecordStart`、host 確實收到事件或磁碟保存成功 |

`DoLoadNewICTray_9050` 的三條 return-true 路徑是 case 1／250／400，不能拿 true 當有效 IC／UPH 取樣完成的證據。三個所選完整函式各自經 lexical masking 後，`bRecordUPH`、`iUPH_LoaderCount`、`CalculateUPH`、`AddLoadingCount` 都零命中；這只涵蓋這三個本體，不是 HT9050 所有間接寫者或取樣鏈不存在的證明。

`DoLoad_9050` case 1000 的 `SOFT_SIMULTE` 分支設層數 5，是所選模擬程式常數，不能拿來作真機層數或 UPH 容量。探盤 helper、教導／快照、其他 Task 的完整機台意義仍待查。

[取料caller子樹](catch/index.md)續查InitialCatchFromLoader_9050／DoCatchFromLoader_9050及DoCatchTray case250；取料Task1、層數與Tray欄位只作本地狀態證據，並未閉合UPH每顆計數。
