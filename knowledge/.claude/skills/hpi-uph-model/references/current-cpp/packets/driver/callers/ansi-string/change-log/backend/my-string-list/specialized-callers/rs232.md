## GetLastLine

`Rs232Support.cpp::TMyStringList::GetLastLine` 用 GetFileName 取路徑。
只有 FileExists 時才 new TStringList、LoadFromFile、以 File->Count 計數、Clear／delete；
結尾記 sLastFileName 並回 iCount。沒有 Handler 的 Win32 probe→ifstream／getline 鏈。
LoadFromFile 的完整部署 IO／例外與行切分需循既有 backend；
這段沒有 try/catch，例外時不能假設暫存 File 必定已 delete。

## MyInsertToFile

`MyInsertToFile(int iCount)` 在 AutoSave false 或 MyList Count==0 時早退。
與 Handler 的兩參數版本不同：要保存的文字來自內部 MyList->Text，
經 AnsiString proxy 後 SubString(0, Length()-2)，再在第 12、26 字元位置插空格。
這是 byte／index 操作，不是通用 CSV／Unicode 欄位轉換；
字串短、內含換行與前批 AnsiString 0／1-based 語意要分開查。

sLastFileName 不存在時先換 GetFileName，否則 LoadFromFile。
之後不論原檔存在與否都繼續選 Insert／Add、SaveToFile；
這與 Handler「原檔不存在只換名稱，該次不寫 Msg」的分支不同。
條件同樣是檔案存在、File Count>iCount 且 iCount>0 才 Insert，否則 Add。
正常走完會清 File、MyList 並 delete File；沒有 try/catch 或保存回執，
遇到例外時不能套用 MySaveToFile 的「即使開啟失敗仍 Clear」結論。
