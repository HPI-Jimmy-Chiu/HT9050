# Data Analysis Skill (HT9045 State Record)

本 Skill 用於「機台異常排查」場景，特別是使用者提供 `Task_ListWithTime.csv`
（由 `DoStateRecord` 產生）時，快速找出：

1. 問題發生時間與站點
2. 卡住的 State/Task
3. 前後關聯事件
4. 最可能根因與下一步驗證

## 何時使用

在下列情境優先啟用本 Skill：

- 使用者說「機台卡住 / 當機 / 停機 / timeout / cycle time 變長」
- 有 `Task_ListWithTime.csv`
- 需要快速摘要「核心問題」而非全文逐行解讀

## 必要輸入

最少需要：

- `Task_ListWithTime.csv`

若可取得，請一併納入：

- `Error/` 相關 log
- 當日設定檔（如 `system/ATC.ini`, `config/config.ini`）
- 事件時間點（例如操作員回報時間）

## 分析目標

產出必須回答以下問題：

1. 異常從哪個時間點開始？
2. 停在什麼 State/Task？持續多久？
3. 異常前一個正常動作是什麼？
4. 是否為單點異常（偶發）或固定流程重現（必現）？
5. 最可能根因是：感測器、馬達軸、通訊、治具/機構、流程邏輯、或參數設定？

## 快速分析流程

1. 先做資料健檢
- 檢查 CSV 欄位是否完整（時間、State/Task 名稱、耗時或狀態欄位）。
- 先確認時間序是否遞增，若有跳時/倒序，先標註資料可信度風險。

2. 抓異常區段
- 以「超長耗時」「重複 State 不前進」「Error/Alarm 關鍵字」為優先切點。
- 先圈出異常前後各 20~50 筆紀錄作為最小分析窗。

3. 找卡關點
- 找出最後一個成功切換的 State。
- 找出第一個異常延遲或重複出現的 State。
- 計算該 State 的停留時間與重試次數。

4. 做關聯判斷
- 若同一 State 連續重試且無後續進展：優先懷疑感測器訊號未到位或動作完成條件未成立。
- 若跨多模組同時延遲：優先懷疑通訊或上位控制阻塞。
- 若只在特定 recipe/型號發生：優先懷疑參數或教導資料偏移。

5. 給出可執行結論
- 必須提供「根因假設排序（Top 3）」與「每個假設的最短驗證步驟」。

## 常見異常模式對照

1. State 重複循環
- 現象：A -> B -> A -> B 或同一 State 重複 N 次
- 常見原因：到位訊號抖動、條件判斷邏輯未鎖定、重試機制未設上限

2. 單一 Task 耗時暴增
- 現象：某 Task 平均 1~2 秒，異常批次變 20~60 秒
- 常見原因：機構阻力上升、等待外部設備回覆、timeout 門檻不合理

3. 多站點同步變慢
- 現象：非單站點，整線節拍同時下降
- 常見原因：共享資源阻塞（通訊、資料庫、互斥鎖）

4. 異常前有切線/換批/換參數
- 現象：異常緊接 setup 變更後
- 常見原因：config/ini 參數不一致、對應表欄位錯置

## 執行原則

- 先給結論，再給證據。
- 不只描述現象，必須明確指出「卡在哪個 State/Task」。
- 若資料不足，清楚列出缺少哪些檔案與為何會影響判斷。
- 回覆要能直接給現場工程師執行，不使用空泛描述。
