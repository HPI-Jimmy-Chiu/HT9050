### G.3 D-5 評估：保留 `TMyEtherCatMotor` 並整合同事成果 —— **可行，而且我同意**

但它**不是程式碼合併，是分層**。理由與做法：

**(a) 兩者不是同一層的競爭者。**
`TMyEtherCatMotor` 是 `HTMotor` 的後端，服務的是**手臂狀態機**
（`MOT[]`，由 `ainarm*` / `csystem` 驅動）。
`Pci1203Control` 是**給 web/tag 客戶端的命令派發面**，服務的是**操作員按診斷頁的按鈕**。
兩者呼叫同一組 `Acm_*`，但呼叫者不同、生命週期不同。

**(b) 同事那邊真正不可取代的，不是運動呼叫。**
`Acm_AxMoveRel` / `AxHome` / `AxJog` 兩邊本來就都有（實測：`TMyEtherCatMotor` 用 37 個
`Acm_*`、`Pci1203Control` 用 21 個，運動那一組完全重疊）。他獨有而且珍貴的是四樣：
- **軸↔站對應**（量出來的，錯過兩次、方向相反，現在用「問從站本人讀 `index+0x800`」判雙軸，
  並用「每站數量加總 == `FT_DevAxesCount`」當守衛）
- **驅動器參數層**（`Pci1203Gear.h`：齒輪比、`2701h→2700h→1010h` 三步、
  `Pn50A/Pn50B` 的**讀-改-寫**。他的 README §4 寫明：寫一個裸 `8` 進去會把 `/S-ON` 清掉，
  **那顆軸再也無法激磁**，比極限沒關掉嚴重得多）
- **診斷層**（142 個警報名、ring 活性、「這一軸現在動不了的原因」）
- **一條知識**：`Acm_*` 回 SUCCESS ≠ 機台做了事

**(c) 所以整合的形狀是：**
| 元件 | 歸屬 |
|---|---|
| `TMyEtherCatMotor` | **保留**，且是**生產期唯一**下運動命令的東西 |
| `Pci1203Gear.h` | **共用**。他的 README §7-1 明講：拆開抄會得到兩份各自漂移的索引算式，**而且兩邊都會回 SUCCESS**，機台上看不出來 |
| `Pci1203Monitor` | 唯讀觀測，已落地（BU-C1） |
| `Pci1203Control` | **保留，但範圍限定在診斷／bring-up 頁**，不進生產運動路徑 |

**(d) 兩個硬約束：**
1. **`TMyEtherCatMotor` 必須改用同事的軸定址。** 它現在走
   `Acm_AxOpenbyID(uiDevhand, iBoardID, iPortID, ...)`（`myEthercatmotor.cpp:384`），
   參數來自 `Mot_Table.csv`。而 `Acm_AxOpenbyID` 的第 3 參數是**扁平軸池的位移**，
   **站號會被驗證、sub-index 不會**（他的 README §1）——所以填錯只會安靜地開到別的軸。
   **好消息：沒有相容包袱。** 實測 `Mot_Table.csv` 45/45 列 `CardModel` 都是 `SMC`，
   **零個 PCI1203 列**，所以從來沒有既有的 1203 對應表要遷就。
2. **一張卡只能有一個 owner。** `TMyEtherCatMotor` 自己 `Acm_DevOpen` 進全域
   `uiDevhand`（`myethercatmotor.cpp:327/374`，該全域已有 6 個檔在用）；
   `Pci1203Monitor` 有自己的 handle，並且提供 `Pci1203ModeAttached` 可以掛在已開啟的裝置上。
   ⇒ **一個擁有、其餘 attach。**

**(e) 由這題掉出來、還沒答的一題（列進 BU-C4）：**
同事的架構裡 **`wb_publish` 是一個獨立行程**（開卡、跑 pump、持 8046），
而 `TMyEtherCatMotor` 活在 handler exe 裡。**兩個行程開同一張卡**是另一個層級的問題。
