# F5 與開發驗證的共用建置規則（Jimmy，20261007）

適用 V906 C++ 移植樹，涵蓋機台端 IOWEB F5、同事／筆電 F5 與一般建置。

## F5／手動功能驗證

F5、一般 build.bat、Ctrl+Shift+B 只建 wb_serve 及必要依賴，開啟既有 HMI。所有入口設定 BUILD_TESTING=OFF；機台端三種直接 CMake 的 F5 也先重設這個選項，再建 --target wb_serve，避免既有 cache 曾開啟測試而繼續受測試宣告影響。

不編 test_*、不執行 CTest、relevance helper、probe、全目錄 PE 或 MD5 驗證工具。F5 的 Debug／SIMULATION／SHIPPING 與 SDK、機台參數保持原組態；本規則不代表更換機型或武裝硬體。

## AI／開發期間驗證

測試工具與原始碼保留。需要驗證程式改動時，明確執行 build.bat gate；預設使用 Obj/V906/build_tests，啟用 BUILD_TESTING=ON、建置測試並依既有規則驗證。build.bat test 只跑已設定的開發目錄，若沒有 BUILD_TESTING=ON 或 CTest 登記檔，會提示錯誤，不把「沒有測試」報成通過。

開發測試需要完整的版控測試資料（包括 machines/HT9050 與 web）。精簡／sparse 工作副本若漏了這些資料，應先補齊版控內容；不能把缺少測試資料當成機台功能錯誤，也不能為了通過設定而刪除測試。這不代表把 snapshot 套入 system/，不更動機台執行期參數。

多個 AI 不得同時使用同一建置目錄。可指定獨立 V906_BUILD_DIR，例如 build_tests_<工作代號>；兩組態應分開目錄。禁止 gate/test 使用 build、build_dbg、build_ship、build_integ_* 等一般建置或 F5 目錄。

BUILD_TESTING 是「是否納入測試」的開關；W906_TEST_BUNDLES 是「如何打包測試」的開關，OFF 不代表停用測試。ht9045_testercomm 是主程式與測試機通訊的必要模組，不能因名稱有 tester 就刪除。純 probe 排除於 ALL，但明確需要時仍可指定目標建置。

## 重複宣告經驗

20261007 的 F5 代碼 1 是當時工作樹重複登記 test_staterecord_archive／StateRecordArchive，CMake 在設定階段拒絕同名目標，尚未編譯所以 build_last.log 仍是前一次紀錄。修復需刪除重複登記，不能靠「仍偵錯」或清除編譯目錄解決。

公司 origin/main 當時只有一份該宣告，不能宣稱所有人已有同一錯誤。其他同名測試可能在 W906_TEST_BUNDLES 的互斥分支，sqlite3 也依來源走互斥分支；不可只用文字重複就刪除。AI 整合測試清單後，應在獨立開發目錄以 BUILD_TESTING=ON 設定專案，確認實際生效的宣告沒有衝突。日常 F5 不載入 tests，開發驗證仍需檢查測試設定本身。

## 交付及驗證界線

此規則以公司 GitLab 的獨立分支／MR 分享，合併後同事需更新自己的工作樹；機台端依既有更新包交付流程取得，發布 MR 不代表已更新機台。不可把私有 GitLab 歷史推到公開 GitHub。
