#### 0.1 CONFLICTS open item 1 (A4) -- answer

Census of `SetPosition` / `SetCommand` (126 hits) plus every wrapper that reaches a card (`PCIL132_SetPos`, `PCIL132_ResetPos`, `<card>::ResetPos`,
the `InitMotor` tail, Galil `"DP"`, direct `kCmdAxSetCmdPos/ActPos`), all live callers enumerated (section A8). **Live outside HOME on HT9050:**
1. **Servo-on re-sync** (A8-1): after a JAM servo-off (`bAlarmNeedServoOff`), EMG release, AutoClean pin release and the Motor Test servo button. With
   MOTION_CARD_TYPE=0 the call is the SYN arm `ResetPos()` = **write 0** -- refused on DS402, which today protects the arm. The open risk is the other way:
   if `Acm_AxSetSvOn` does not re-sync the command to the actual position, an arm pushed by hand during the servo-off is not brought back.
2. **Reload Motor Data** (A8-3): writes 0 directly on every opened axis, DS402 included (EastSun 0925 ruling MT-E1 allows exactly this; Q1 1003 refuses it on the route).
3. **`InitMotor1203`** (boot M35, Test Range / Rate): writes 0 directly -> R210 #8.
4. **Galil `DP`** `TestZ1SetPos` -> R210 1-9.

Everything else is HOME-only, unreachable on HT9050 (belt-stepper wrap, OCR, magnetic scale), memory-only (MLoaderY has no row), or not a motor:
the "one `SetPosition` in each `ainarm9045*` variant" is `HPPlaceLog.SetPosition()`, a hot-plate placement log (K5).
