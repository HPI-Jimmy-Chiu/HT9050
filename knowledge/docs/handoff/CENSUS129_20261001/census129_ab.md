## 5. Ranking, confidence, false-positive shapes

Confidence = 100 x P1 x P2 x P3 -- "golden does X, the port does nothing or a constant, and the port's dependencies for X exist".
* a1: P1 = match level (L1 0.95, L2 0.85 unique / 0.7, L3 0.6, L5 0.75 / 0.6, L6 0.6); P2 = 0.95, x0.6 if the stub is not a stub under the other macro policy, x0.4 if the file is not in any CMake target, x0.3 if the golden statements already live elsewhere, x0.8 if the port comment states intent; P3 = 0.4 + 0.6 x (share of golden callees/objects that resolve to a definition).
* a2: P2 = 0.95 x sqrt(1 - cov_any).
* gates: P1 1.0 (verbatim text in tree) / 0.5 (placeholder without text); P2 by ST02 class (KEEP_DECISION 0.72-0.9 depending on the stated reason, none/unreviewed 0.55-0.6, claimed 0.4, blocked 0.35); P3 as above; COMMENT gates x0.6.
* Caps: tool-derived a1/a2 <= 85, gates <= 80; only hand-read rows exceed that. Held/design/false-positive hand rows are capped at 25-35.

False-positive shapes met (and handled): (i) `body_size_scan`: bodies that are entirely commented out in golden (TLaneIO::SetUseIP), forwarders to a renamed body (DoBottom2DIDScan -> BarCode_*, AddEC/AddSV), overload collapse (WriteIniData 183 vs 46), brace-unbalanced golden (GetShuttleCol), ladders moved to another function (DoAllProcess -> W906_DoAllProcessLadder); of the 69 hits 44 are in a1, 7 in a2, 18 in neither. (ii) a2 statement-set coverage is sensitive to spelling: `RENESAS_CMD.OnLineCMD()` vs member `OnLineCMD` gave coverage 0.07 for a faithful function (CheckInputCommand, marked FALSE-POSITIVE); TU-local prefix rewrites (`W5FA_LS_BinCT`) also lower coverage but there the stand-in IS the defect. (iii) by-name caller counts overstate for file-local statics (recounted same-file with `recount_static.py`: 59 static free-function candidates, 25 reach only through a macro alias). (iv) A macro-seam `Name` and its `PREFIX_Name` stub are one finding, not two (double-apply hazard: retire the seam, never copy golden text into the stub). (v) stale port comments that overstate the gap (InitInArmTask "no-op stub" is already retired).
