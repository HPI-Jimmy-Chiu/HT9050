## 0. 結論

**有條件可行。**另外，**RS232 在 HT9050 上本來就走不通**，所以實際上沒有「RS232 或 1203 二選一」的問題。

1. HT9050 只有**一支** Index Z：`MTestZ1`（M14）。驅動器是 Yaskawa Σ-X `SGDXS-200AA0A0002`（EtherCAT），馬達是 `SGMXA-30AUA6CA2`（3 kW、帶煞車），掛在 1203 ring 0 的站 14。`MTestZ2` 在 HT9050 上不存在。【量】
2. golden 的 RS232 扭力程式只講三種協定：Panasonic MINAS 封包、三菱封包、鴻勁 HP 通訊卡。Σ-X EtherCAT 驅動器三種都聽不懂【推，把握高】。另外 HT9050 規劃的 COM1～COM6 都已經有用途，其中 COM1 是 BIN；golden 扭力埠的預設值正好是 COM1【量】。
3. 1203 這邊已經有一套受閘管控的 SDO 讀寫框架：`Pci1203Control` 負責寫，`Pci1203Monitor` 負責讀。它有白名單、有 dry run、有稽核紀錄、有站號驗證，gate 腳本也會限制 SDO 可以寫的 index。**缺的只有**：一個新的命令 kind、gate 白名單新增一筆、一個給 golden 流程呼叫的入口。【量】
4. 條件：以下幾件要上機量過或請 EastSun 確認，才能決定寫哪個物件（見 §6）：
   - PDO 映射：6077h 有沒有在 TxPDO 裡；60E0h／60E1h 有沒有在 RxPDO 裡（有的話 SDO 寫進去會被週期資料蓋掉）。
   - 2704h（轉矩使用者單位）的單位語意。
   - 60E0h 和 Pn402 同時存在時，哪一個生效。
   - 站 14 的站號現在是否唯一。20260916 量到它跟另一台撞號。
   - 下壓時扭力被限住，會不會觸發位置偏差警報（Pn520／A.d00）。

**建議的 1203 端做法**（§5 有細節）：
- 新增 `kCmdAxSetTorqueLimit`：正反兩個方向寫同一個值，寫完讀回比對。**不做** 1010h 存檔，**不呼叫** `ForceGearReread`。
- 實際扭力 6077h 用有節流的單站 SDO 讀取。如果上機量到它已經在 PDO 裡，或廠商屬性讀得到活值，就改走那條免信箱的路。
- 寫入物件：首選 Pn402／Pn403（2402h／2403h，單位 1%，跟 golden 的「%」一樣，不受 2704h 影響）；次選 60E0h／60E1h（必須先驗 2704h 是 1/10）。

### 2.1 單位換算

- **golden 的值是「% 額定扭力」**【量＋文】：
  - Panasonic A5 寫入封包 `{0x06, 0x00, 0x17, 0x00, 0x0D, ...}`（golden `rs232.cpp:1426`），也就是參數 Pr0.13「第 1 扭力上限」；A4 是 `0x5E`（`:1453`）。這兩個參數的單位都是 %【文】。
  - 三菱分支有 `if(Torque>100) Torque=100;`（golden `rs232.cpp:1873-1874`）。
  - 還原值 300（`atester.cpp:6423`／`:7072`、`uhome.cpp:2299`：`iWriteAndCheckMotorTorque(0, 300)`）= 300%。
- 換算表：

  | 寫到哪裡 | 換算 | 標記 |
  |---|---|---|
  | Pn402／Pn403 | = v（%） | 【文】 |
  | 60E0h／60E1h（或 6072h） | = v × 10（‰），**前提**是 2704h = 1/10 | 【推】 |
  | 6077h 讀回 → golden 的 % | ÷ 10，同一個前提 | 【推】 |
  | ‰ → N·m | × 6076h(mN·m) / 1000 / 1000 | 【文】 |

- **【注意】配方值不能直接沿用**【推】：「%」是相對各自馬達的額定扭力。HT9045 的 Panasonic Z 馬達和 HT9050 的 SGMXA-30（量到 9800 mN·m）額定扭力不同，同一個 `Prod.iMaxPreasure` 在兩台機上是不同的扭力，也就是不同的下壓力。HT9050 的配方值要重新校。

### 3.1 誰在呼叫 SDO

### 3.2 同步還是排程、在哪條執行緒

- **同步**：`Execute()` 裡直接呼叫、直接等回傳（例 `Pci1203Control.cpp:1792`：`ret = Acm_DevWriteSDOData(dev, 0, (U16)a.station, idx, ...)`）。每筆 SDO 花多少時間**沒量過**；R35 估 400 筆是 0.4～4 秒（`docs/nb2_assist/README.md` R35）【推】。
- **單一執行緒**：`Pci1203Control.h:802`：`Not thread-safe, and driven from the SAME thread that polls the monitor -- the vendor API is called from exactly one thread everywhere in this tree.`
- wb_serve 主迴圈每一圈的順序是 `PumpTick() → Pci1203AxisIniTick()`、`Pci1203Monitor()->Poll()`、drain＋dispatch，全部在同一條執行緒（`tools/wb_serve.cpp` 主迴圈註解 `AI(W906-Q34-7)`）【量】。
- ⇒ golden 流程 `MainProc → DoTestHeadMotor → COM2->iWriteAndCheckMotorTorque` 本來就在 `PumpTick` 裡跑。在那裡直接呼叫 1203 的扭力函式，不會違反「只有一條執行緒呼叫廠商 API」這個前提【推】。

### 3.3 單位處理與錯誤碼

- **單位**：現有的每個 kind 都是把呼叫端給的原始整數照寫（例 `U32 v = (U32)c.value;`，`Pci1203Control.cpp:1790`），模組內**不做單位換算**。⇒ %／‰ 的換算要放在新 kind 或它的呼叫端【量】。
- **錯誤碼**：
  - `Pci1203CmdResult.ret` 是廠商回傳的 U32，`why` 是拒絕理由或廠商錯誤文字，`wouldCall` 是實際呼叫字串（`Pci1203Control.h` 的 `Pci1203CmdResult`）。
  - `Acm_GetErrorMessage` 把回傳碼轉成廠商原文（`Pci1203Control.h:139-147`）。
  - 已知碼：`0x800000EF`（資料大小錯）、`0x8000000A`（不支援這個屬性，`Pci1203Control.h:485-487` 那一段）、`0x80000009`（字串長度，`Pci1203Monitor.h`）、`0x8300002B`（站號衝突，`Pci1203Monitor.cpp:171`）【量】。
  - 要對應 golden 的 `iWriteAndCheckMotorTorque` 語意：0 = 進行中、1 = OK、2 = 失敗（golden `rs232.cpp:1964-1967`、`:1983`、`:2003`）【量】。
- **寫入成功 ≠ 值有被採用**：`AI(W906-1203GEARWHY-1)`（`Pci1203Control.cpp:1846` 起）在齒輪比上實際踩過，所以齒輪比寫完會讀回比對。扭力寫入也要照這個做【量】。

### 3.4 現有的 kind，以及要不要新增

- 現有 kind（`Pci1203Control.h:270-418`）：DO（bit／byte）、SvOn、ResetError、Jog、Stop、EmgStop、MoveRel／Abs／Vel／Impose、Home、SetSpeed、AbsEncoderReset（Fn008）、CardRescan、SetLimit、SetGear、GearApply、SetHome、SetDriveDir（Pn000）、StoreParams（1010h）、SetOtAlloc（Pn50A/B）、GearSetAll、SetEncCompat（Pn21D）、SetDriveHome（6099h/609Ah/607Ch）。
- **沒有任何一個 kind 會寫 6072h／60E0h／60E1h／2402h／2403h**【量】。`kGearTrqNum/Den` 寫的是扭力的**單位** 2704h，不是上限；而且它是 §4.2 風險 5 的來源。
- ⇒ **需要新 kind**（建議名稱 `kCmdAxSetTorqueLimit`）。原因：`Pci1203Control.h:265-268`：`Deliberately a small closed set: a generic "call vendor function X with args Y" bridge would make this file's allowlist decorative`。
- gate 也要一起改（`tools/pci1203_control_gate.ps1`）：
  - **check 5**：每個 `Acm_DevWriteSDOData` 呼叫點的 index 寫法都要在 `$sdoIndexOk` 表裡，而且要附理由（`:651-708`）。新增 `Pci1203TorqueLimitIndex(...)` 這一筆，並說清楚它把可寫範圍擴大到扭力上限。

### 3.5 PDO：6077h 已經在週期資料裡了嗎？

### 3.7 30 秒 SDO 窗口的代價（NB2 R35）

- 一次窗口 = 20 筆 × 軸數（R35 算的是 20 軸，共 400 筆），估計主執行緒卡 0.4～4 秒，沒量過（`docs/nb2_assist/README.md` R35 第 1 點；量測報告 A5 列）。
- **`ForceGearReread()` 會讓「下一次讀卡」整個窗口重跑**（`Pci1203Monitor.cpp:1976-1981`：`the next poll re-reads the gear instead of waiting out its 30 s window`）【量】。golden 每個測試週期寫兩次扭力：12000 寫 `Prod.iMaxPreasure`，12200 寫回 300（`atester.cpp:6150`／`:6423`）。如果照齒輪比命令的慣例在成功後呼叫它，**每個週期會多跑兩次完整窗口**⇒ 每週期可能多卡 0.8～8 秒【推】。

### 4.2 1203 版本新增的風險（都是【推】，待 EastSun）

1. **垂直軸會往下沉**：Index Z 是垂直軸、3 kW、帶煞車。正反兩向寫同一個值，跟 golden Panasonic Pr0.13 的雙向行為一致；但如果值低於抵抗重力所需的保持扭力，Z 在伺服 ON 時可能下沉或抬不起來。HT9045 的配方值換到這顆馬達上，數字意義不同（§2.1）。
2. **位置偏差警報**：扭力被限住壓到底時，位置偏差會累積，可能觸發 A.900（警告）或 A.d00（警報），門檻是 Pn520。卡片端也可能因為 following error 進 ERROR_STOP（`CFG_AxMaxErrorCnt`，`AdvMotPropID.h:526`，語意沒驗）。golden 在 Panasonic 上有同類行為，但門檻要在 HT9050 重新確認。
3. **PDO 覆寫**：60E0h／60E1h 如果在 RxPDO 裡，SDO 寫入會「回 SUCCESS、讀回也對，下一個週期就被蓋掉」。Pn402／Pn403 不在 PDO 裡，沒有這個問題。
4. **站號衝突**：寫到另一台驅動器、而且回報成功（§1.3）。靠閘 5 擋。
5. **2704h 被齒輪比面板改掉**：選 60E0h 的話，操作員在網頁把 2704h 改成 1/100，golden 的「30%」就會變成 3%（差 10 倍），寫入照樣回成功。⇒ 選 A 案必須每次檢查 2704h 是否還是 1/10（監看器已經有 `gearVal[6]`／`[7]`）。Pn402 用固定 1% 單位，不受影響（待手冊確認）。
6. **EEPROM 壽命**：每個週期存檔（1010h）會快速耗掉寫入次數。只寫 RAM 就好，golden 每次下壓前都會重寫；斷電後回到預設 800%，比較保守。
7. **稽核紀錄被洗掉**：紀錄是有上限的 ring。每個週期兩筆扭力寫入會把操作員命令的紀錄擠出去。可以考慮「值沒變就不記」，但要先確認這樣不違反忠實翻譯。

   - `fMain->edtReadZ1/2`：讀回來的上限設定值
   - `fMain->edTorue0/1`：扭力回饋字串
   - `GetReadTorueTask()==999`：讀取結束的標記值
   - `fMain->chkReadTorque1/2`：觸發讀回饋的勾選框

   golden 自己已經在 4 個分派函式裡依 `TorqueUseHPComCard`／`INDEX_DRIVER_TYPE` 分成三路。所以 HT9050 最小的切法是在這 4 個分派函式和 `RS232Init` 加第 4 路。golden 裡 40 個寫入呼叫點、76 個讀取觸發點（全樹 grep 的文字命中數）都不用動。【量＋推】
3. **單位**：
   - `Prod.iMaxPreasure` 在 golden 被寫死成 120（`golden:cinitial.cpp:12016`），單位是「額定扭力的 %」：Panasonic 寫的是 Pr0.13／Pr5E，主畫面印成 `1: %s %%`。
   - `300` 的意思是「放開到最大」。三菱先夾到 100，再乘 10（0.1% 刻度）寫入。
   - CiA402 的 0x6072／0x60E0／0x60E1／0x6077 單位是千分比 ⇒ 寫入值 ×10、回饋值 ÷10。【量＋文】
4. **HT9050 沒有 RS232 扭力硬體**【量＋推】：
   - IO_Table 裡 `SwReadTorue` 的 Enable=0。
   - MTestZ1 是 1203 站 14 上的 Yaskawa SGDXS，不是 Panasonic 或三菱。
   - MTestZ2 的 Enable=0，硬體清單上也沒有這一軸。
   - 沒有 `SwIndexChangeToque*` 這兩個點。
   - `machines/HT9050/` 沒有 Gerneral.ini。
5. ⚠ **最要緊的一條**：
   - golden 的 START Index 檢查（DoTestHeadMotor 的 case 120/12000 與 140/14000）**沒有任何「有沒有扭力硬體」的閘**，只有 `SOFT_SIMULTE`。唯一檢查硬體在不在的地方是歸零流程（uhome 310 的 `SW[SwReadTorue].Enable`）。
   - c55e2954（已在 origin/main）把 RS232 扭力翻成活的。之後，HT9050 出貨組態按 START 時，會在 12000 寫扭力、收不到回應，約 100 秒後報「Motor torque set error」並把 `fAllMotorHome` 設成 false【推】。
   - 所以 HT9050 分流不是加分題，出貨前一定要處理。
6. **可行性（golden 側）：有條件可行**。golden 對呼叫端的契約很窄、呼叫端也集中，換掉後端不必動流程。條件有三：Yaskawa 端的物件與單位要確認、1203 的 SDO 寫入白名單要開、HT9050 沒有 Z2 這件事要裁決（§4、§5）。
7. **Q6 報告的 port 行號已過期**：
   - `csystem.cpp:29974/29988` 的 `#if 0` 和 `atester.cpp:5605` 回 1 的替身，都已被 c55e2954 拿掉。現在是 `port:csystem.cpp:29983`／`:29996` 的活呼叫，`port:atester.cpp:5629` 會轉呼叫真的 COM2。
   - 另外，request 寫「main.cpp ShowMainScreenPresure」，但它在 golden 其實在 `cinitial.cpp:13816`（宣告在 `cinitial.h:39`）。

  2. 沒有回應，10 s 後參數逾時（`golden:rs232.cpp:1536-1541`）。

### 3.4 建議切法（golden 側觀點）
