## 2. 第二題：按鈕能不能經 HT9050 的 1203 控馬達？——**程式路徑有，而且是實彈的；但從沒在真卡上跑過，且要同時滿足下面四個條件**

**鏈路**：頁面 → WS `motor.access` → `wb_serve.cpp:4982` → `MotorAccessDispatch`（`WebMotorAccess.cpp`）→ `TPci1203Control::Execute` → `Acm_*`（`Pci1203Control.cpp:1720-1745`、`:2029`）。

**條件**（缺一個就不會動，會被拒絕並說出原因）：

1. **wb_serve 要在找得到 Advantech SDK 的機器上建置**。
   * 只有這樣，**wb_serve 這個 target** 才會帶 `HAVE_PCI1203=1`（✔ `CMakeLists.txt:3329-3346`）。
   * `MachineType.h:105-106` 的 `WB_PUMP_1203_CONTROL`／`_LIVE` 已經打開，`:159` 開機會啟動 ring 0。
   * ⚠ `ht9045_io`／`ht9045_motor`／`ht9045_sm` 三個函式庫**刻意沒帶**這個旗標（INBOX #18）。
     * golden 的馬達類別與 IO 走不到 1203。
     * **MotorTest 按鈕不受影響**：它們繞過 golden 馬達類別，直接呼叫 EastSun 的 `Pci1203Control`，而那兩支檔編在 wb_serve 裡。
     * **受影響的是互鎖**：互鎖讀的是 golden IO，在非模擬建置下會讀到樁回來的 0（見 §4）。
   * 版本至少要到 `9dd66076`：在 `02f22d05` 那一版，模擬建置會把 Const Move、Go、Loop 全部誤擋；JOG、HOME、Servo 那時已經會動。
2. **頁面要是 C++ 模式**：`motorSrc='C++'`，而且操作端持有 control token。
3. **軸要能對到監看器開成功的軸**：
   * 對應規則是 Mot_Table 的 `(BoardID, Port)` 必須**剛好等於**一個監看器開成功的 `(station, stationAxis)`（✔ `WebMotorAccessLive.cpp:9-13`、`:73-91`）。
   * ⚠ **M20 的問題**：
     * git 版的 HT9050 Mot_Table 裡，M20 的 BoardID 是 20。
     * 20260912 實測的 SERVOPACK 站號只有 0/1/3/10/14/30/41/124/153（✔ `MachineType.h:144`）。
     * ⇒ **照 git 的表，M20 的每一顆位置類按鈕都會被拒絕**，訊息是「1203 監看器找不到 站 20 軸 0」。
     * 機台上的 Mot_Table 有 7 列 BoardID／Port 沒進 git（`INBOX_QUEUE.md:45` #13），**所以 M20 到底會不會動是 UNKNOWN**。
     * git 表中 19 個啟用中的 1203 軸，BoardID 落在實測站號裡的只有 M00、M01、M03、M14、M30、M41；其中 Direction=0 的只有 M03、M30、M41。
4. **Mot_Table 條件**：`Enable=1`；位置類命令（JOG、Const Move、Go、Loop）還要 `Direction=0`（`WebMotorAccess.cpp:459`；裁決 6B「1203 軸忽略 Direction」還沒實作）。

## 3. 新電腦這一波可以動手的（檔案:行＋改法＋驗法）

### 3-1 ⚠ Loop Move 送 pos1=pos2=0（安全相關，先修）

## 4. 機台旁按按鈕之前（安全提醒）

* **機台預設建置是 `SOFT_SIMULTE` 開＋LIVE＋有 SDK**（`NIGHT_REPORT.md:329`）。在這個組合下，golden 互鎖是**盲的**，但 1203 的運動是真的：
  * 門：✔ `csystem.cpp:20893` 用 `#ifndef SOFT_SIMULTE` 把門掃描整段跳過。
  * ✔ `cinitial.cpp:4011-4012` 在模擬建置下把 `Motor->Enable` 設成 false，所以不會掛 `MotorIdleSafeDoorCheck`。
  * EMG：HT9050 `IO_Table` 裡四顆 EMG sensor 都是 `Enable=0`，**任何建置都不會檢查 EMG**。
  * ⇒ **網頁不會因為門開著而擋移動**。剩下的保護只有驅動器／硬體 EMG、STO、硬極限。
* **非模擬建置則相反**：1203 的 IO 走樁（`IOBackend.cpp:169-174`，INBOX #18），互鎖讀到 0。
  * 安全門很可能讀成「開」，大部分移動會被擋。
  * 機台端的 IOWEB-P17（1203 IO 走監看器）還沒進 main。
* **Loop Move 在 3-1 修好之前不要按。**
* **先確認機台跑的是哪一版**：
  * 最後一次交付是 `02f22d05`，早於 W4-d：沒有 HOME 的門檢查與 HOME 速度。
  * 機台上另有未進 git 的 IOWEB-P1～P17 與 4 個改過的 config 檔。
* 放開 JOG 的死人開關只在 token 持有者消失時才生效（`WebMotorAccess.cpp:1150-1157`）。**分頁卡住但連線還在時，軸會一直跑。**
* Stop 和讀卡排在同一條執行緒，延遲推估 0.4～4 秒，沒量過（NB2 R35）。
* 垂直 1203 軸（M03、M22、M35～M40）上按 Servo Off 會直接送 SvOn 0；golden 的斷電路徑會先顧 Z 軸煞車。**煞車行為 UNKNOWN**。
