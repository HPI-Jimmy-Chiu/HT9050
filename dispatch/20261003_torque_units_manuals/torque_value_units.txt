HT9050 drive torque value -- what the machine reads back (machine side, read-only check 2026-10-03; for Jimmy, EastSun asked)

Answer: a PERCENTAGE of the motor's RATED torque, resolution 0.1 % (one decimal place).

How the tree reads it
  - SDO: object 6077h Torque actual value (axis B of a 2-axis SGDXW: 6877h = +0x800), INTEGER16 (ECAT_TYPE_I16),
    only the selected axis, at most once per poll -- EtherCAT/Pci1203Monitor.cpp:3386-3389.
  - PDO: Acm_AxGetActTorque every poll (32-bit; its unit is not documented in the Advantech header) -- trusted only after
    3 agreements in a row with the SDO value; the SDO value wins when both exist -- Pci1203Monitor.cpp:3381-3393,
    Pci1203Monitor.h:1723, 1754-1758.

Scaling
  - % = raw x 2704h:1 / 2704h:2 (2704h = Torque User Unit, Yaskawa SIEPC71081205 section 14.6.6) -- Pci1203Monitor.cpp:3446-3453.
  - Measured 2026-09-15 (code note): 2704h = 1/10 on every axis (Yaskawa default) -> raw 1 = 0.1 % rated torque, % = raw / 10
    -- Pci1203Monitor.h:920, 1747-1748.
  - N.m = % / 100 x 6076h / 1000 (6076h = rated torque in mN.m, 320 .. 9800 on this machine) -- Pci1203Monitor.cpp:3455-3460.
  - 2704h not read (either half 0) -> no % (page shows ---), never 0.
  - Range: INT16 -32768 .. 32767 = +-3276.7 %; the real limit is the drive's max torque 6072h (not checked).

Page
  - C++ sends pct as a float (JsonBridge/ChanMotorPoints.cpp:292); HW.MotorTest.html:426 shows
    (Math.round(pct*10)/10).toFixed(1) + ' %' -> one decimal = the raw resolution. PDO-only and not yet compared with the
    SDO -> the page marks "unit NOT verified" (HW.MotorTest.html:431).

Notes
  - If someone changes 2704h the resolution changes but the page still shows one decimal.
  - The Yaskawa manual page for 6077h was not opened this time (no PDF text tool on the machine); the 2704h basis is the manual
    section the code cites. CiA 402 standard (general knowledge, not measured): 6077h INTEGER16, unit per thousand of rated
    torque (0.1 %).
  - Index Auto Height (dispatch 1, NB2-1 R197): golden's torque value has a different unit (10x) and sign follows direction --
    wiring this % straight in could make the threshold never trigger.
